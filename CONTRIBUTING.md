# Вклад в Kafedra Planner

Спасибо за интерес к проекту. Kafedra Planner хранит рабочие документы и
подтверждённые факты кафедры, поэтому небольшое изменение должно сохранять
provenance, права доступа, идемпотентность и автономную работу без Интернета.

## Перед началом

1. Посмотрите открытые [issues](https://github.com/f2re/kafedra-planner/issues) и создайте issue для существенной работы.
2. Создайте короткую ветку от актуального `main`.
3. Прочитайте [архитектуру](docs/ARCHITECTURE.md), [правила UX](docs/design.md) и профильную документацию изменяемого контура.
4. Не добавляйте обязательные облачные сервисы, CDN, Docker или LLM-зависимости в пользовательский сценарий.

## Локальная проверка

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run check
npm test
npm run smoke
```

Если изменение затрагивает браузерный сценарий, запустите относящийся к нему
Playwright-набор. Для поставки и миграций обязательны проверка bundle и
backup/restore; полный перечень находится в [README](README.md#разработка-и-проверка).

## Pull request

Опишите проблему, решение, проверенные команды и ограничения. Не смешивайте
рефакторинг с несвязанной функциональностью. Перед merge обязательны успешный
CI, отсутствие неразрешённых замечаний и проверка требований безопасности.

## Security

Не публикуйте PIN-коды, пароли, токены, реальные документы или персональные
данные. Уязвимости отправляйте по процедуре из [SECURITY.md](SECURITY.md), а не
в публичный issue.
