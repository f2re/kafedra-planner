# Дизайнеры Кафедра-планера: договорённости и задания

Точка входа: `.agent/skills/designer/SKILL.md`. Это контракты задач для доступных исполнителей, не новые службы приложения и не утверждение, что агенты уже запущены. Существующие `kafedra-*` роли сохраняют полномочия.

## Координатор

Прочитать AGENTS, Designer, текущий реестр и PLAN. Зафиксировать commit и границы задания. Сверить каждый исходный элемент, окно, форму, обработчик и сценарий с владельцем. Разделить подтверждённые недостатки, риски и непроверенные состояния. Выдать ограниченные задания, согласовать общие компоненты до параллельной правки, затем провести интеграционную проверку. Не заменять реестр списком разделов.

## Проектировщик сценариев — Impeccable / kafedra-design

Для назначенных идентификаторов изучить реальное создание DOM, обработчик, API и существующий тест. Описать вход, минимальный путь, вторичные действия, состояние объекта, отказ и восстановление. Сократить ненужный выбор, не скрывая независимые операции. Передать изменение компонентов и критерии приёмки. Сохранить данные, права, происхождение и возврат к контексту. При отсутствии установленного Impeccable пользоваться локальными контрактами, не имитировать вызов внешнего навыка.

Предметные зоны одного и того же проектировщика могут выполняться разными доступными агентами:

| Зона | Область | Основной владелец | Независимая приёмка |
|---|---|---|---|
| D1 | Оболочка, навигация, календарь, поиск, личные подстановки | kafedra-design + flow-intake | kafedra-design-audit + tests |
| D2 | Планы, исходные строки, генерация, архивы, План / факт | kafedra-design + feature | kafedra-design-audit + tests |
| D3 | Заседания, повестка, перенос, протоколы, шаблоны выпуска | kafedra-design + feature | kafedra-design-audit + tests |
| D4 | Документы, структура/извлечение, поручения, распоряжения, материалы | kafedra-design + feature | kafedra-design-audit + tests |
| D5 | Научный реестр, импорт, жизненный цикл и отчёты | kafedra-design + feature | kafedra-design-audit + tests |
| D6 | Учебные ведомости, сопоставление, сводки и история | kafedra-design + feature | kafedra-design-audit + tests |
| D7 | Вход, доступ, сотрудники, оргструктура, интеграции, доставка уведомлений | kafedra-design + профильный владелец безопасности/данных | kafedra-design-audit + tests |

D1 владеет общими `app.js`, `ux-base.js`, `styles.css`, навигацией и контрактом окна. D4 передаёт ему изменения общих инспекторов; D2 — изменения календарных продолжений; D7 — изменения меню профиля. Не поручать один общий файл нескольким параллельным исполнителям. Изменение схемы, авторизации или установщика направляется действующему профильному владельцу с проверкой по риску.

## Визуальный редактор — Taste, только при необходимости

Исследовать только согласованную визуальную проблему после определения сценария. Не переделывать рабочие таблицы в карточки и не добавлять рекламные блоки. Предложить ограниченное направление для типографики, группировки и системных токенов. Зафиксировать выбранное решение в `docs/design.md`. Не менять предметную логику, обязательность полей, права или навигационные связи. Отсутствие визуальной проблемы — основание закончить без изменения.

## Специалист по движению — Emil / kafedra-motion

Получить работающий статический сценарий. Для каждого реального перехода описать причину движения, начало/конец, прерывание, возврат фокуса, reduced-motion и нагрузку. Предпочитать `no-motion`, когда переход ничего не объясняет. Не устанавливать внешнюю библиотеку автоматически. Не переносить точные параметры стороннего примера без чтения его исходника.

## Независимый аудитор — kafedra-design-audit

Получить идентификаторы, diff и доказательства, но не принимать самоотчёт исполнителя за проверку. Проверить каждый элемент и все применимые ветви окна/сценария. Вернуть PASS / REVISE / BLOCK с адресами источника и теста. Отделить проверку исходников от выполненного взаимодействия. Отсутствие доступа к браузеру означает непроверенную браузерную приёмку, а не автоматический PASS и не выдуманный дефект.

## Исполнитель и проверяющий тестов

`kafedra-feature` реализует целый предметный путь, а `kafedra-tests` проверяет устойчивый результат и восстановление. На каждое задание указываются конкретные строки реестра, формы, вызовы и семейство сценариев. Общая фраза «проверить все кнопки» не является тестовым заданием.

## Формат передачи

Передавать: зона/идентификаторы → исходный commit и пути → подтверждённая проблема или цель проверки → текущее/целевое поведение → состояния/роли/ширины → минимальное изменение → тест и ожидаемый результат → ограничения → независимый вердикт. Незавершённая или непроверенная строка остаётся открытой. Планирование, реализация и приёмка имеют разные статусы.
