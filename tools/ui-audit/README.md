# Поэлементный реестр интерфейса

Инструмент разработки, не модуль приложения. Не подключается к серверу, БД или браузеру, не нажимает кнопки и не меняет исходники. Зависимости изолированы от основного package.json и автономного комплекта.

```bash
# На машине разработки. Для офлайн-повтора заранее подготовить npm-cache.
npm --prefix tools/ui-audit ci --ignore-scripts
npm --prefix tools/ui-audit test

# Из корня репозитория; создаётся только указанный выходной каталог.
node tools/ui-audit/inventory.mjs . /tmp/kafedra-ui-audit
node tools/ui-audit/check.mjs . /tmp/kafedra-ui-audit

# Быстрая проверка актуальности без сторонних зависимостей.
node --test tests/ui-source-index.test.mjs
```

Node >=20 нужен этому изолированному анализатору; основное требование проекта к Node не изменяется. Для установки из заранее подготовленного кэша применять `npm ci --offline --ignore-scripts` в каталоге инструмента. Ни сторонние дизайнерские навыки, ни Интернет не требуются при работе установленного приложения.

## Результаты

`inventory.json` — подробная запись каждой найденной конструкции: ID, тип, путь/строка/столбец, функция/контекст, подпись/атрибуты, предполагаемый селектор, владелец, начальный профиль приёмки и статус. `sourceCommit: null` означает рабочее дерево: точные байты обозначены `sourceFingerprint`, а не угаданным именем ветки. Исходная версия текущего плана указана в PLAN.md.

`source-index.json` — компактный индекс всех индивидуальных координат и контрольных сумм. Сборщик выдаёт один полный файл. В репозитории исходный снимок хранится как одноимённый манифест и четыре перечисленные в `fileParts` части `source-index-1.json` … `source-index-4.json`. Проверяющий понимает оба представления и сравнивает их логически, не по форматированию JSON.

Каждая запись файла содержит отдельные токены `тип:строка:столбец` в `elements` и `calls`; тип расшифрован в `kindCodes`, владелец наследуется от файла. Все токены сначала запланированы, а не проверены. Например `c:20:9` — конкретная исходная конструкция элемента управления. Строки/столбцы считаются от 1 в UTF-16, как позиции JavaScript, а не по байтам UTF-8. Вложенные выражения могут начинаться в одной позиции; их отдельные ID в полном inventory учитывают конец выражения. Один узел может иметь несколько ролей учёта, например форма и data-кандидат.

`buttons-D1.tsv` … `buttons-D7.tsv`, `windows.tsv`, `screens.tsv`, `forms.tsv` — отдельная строка каждого исходного места. Владелец кнопки указан именем файла D1–D7; у окон/экранов/форм он содержится в столбце owner. `{dynamic}`, подчёркивания и «динамическая подпись» обозначают выражение, а не подтверждённую надпись приложения. Длинные подписи сокращены для чтения; исходный текст восстанавливается по координатам.

## Границы анализа

Acorn разбирает JavaScript, parse5 — HTML, строки и вложенные шаблоны. Анализируются public HTML/JS/CSS рекурсивно и серверный сборщик HTML, программный DOM, известные роли, data-/tabindex-кандидаты, обработчики, делегированные селекторы, вызовы окон/форм и все команды action-registry. CSS учитывается целыми файлами по контракту P01, а не выдаётся за автоматически проверенный контраст.

Граф учитывает статические импорты и серверные вставки. `reachable=false` — задание проверить подключение, а не доказательство мёртвого кода. Вычисляемые импорты/теги/атрибуты, массивы вариантов, динамические формы и совпадения составных селекторов требуют этапа R0. Есть избыточные кандидаты и ограничения статического распознавания. Парсер не выполняет приложение и не доказывает полноту поведения на всех данных. Синтаксическая ошибка останавливает сборку, не пропускает файл молча.

Начальное назначение C01/C02 и других профилей эвристическое: вкладка «Архив» может иметь archive-атрибут, не будучи опасным действием. Исполнитель уточняет смысл, добавляет C04/W01/F01 и иные применимые контракты. Нельзя менять UI по одному такому признаку. Полная матрица обязательств — `docs/design/full-interface/ACCEPTANCE.md`.

## Обновление и доказательства

Получить реестр во временный каталог, сравнить diff исходников и индивидуальных записей. Добавить задания новым элементам, объяснить исчезнувшие и уточнить FLOWS/PLAN. После согласования перенести новый source-index и десять TSV в `docs/design/full-interface/`. Можно сохранить единый полный JSON и удалить больше не используемые части либо разделить его `files` на части и указать их в манифесте. Сборщик не перезаписывает план автоматически.

Доказательства поведения хранить отдельно с ID, вариантом, commit и результатом. Сдвиг исходной позиции может изменить ID: прежний PASS не переносится автоматически. У одного шаблона бывает несколько инициаторов/состояний; нужны все применимые варианты. Владелец физического файла может отличаться от предметного соисполнителя: например адаптер report-match-refresh относится к D1, научный смысл — к D5.

`check.mjs` проверяет перечень исходников, SHA-256, координаты, количества, владельцев, индивидуальные ведомости и при указанном выходном каталоге — воспроизводимость результатов. Root-тест не устанавливает зависимостей и выявляет изменение любого индексированного исходника без пересмотра плана. Проверка сборщика имеет отдельный изолированный набор тестов. Успех этих проверок не равен браузерной приёмке, исправленному интерфейсу или готовности выпуска.
