# Структурные источники и ручные исправления

Версия: `0.1.0-alpha.4`.

## Назначение

Система хранит не только плоский текст документа, но и адресуемые фрагменты. Каждый фрагмент имеет тип, порядок, текст и локатор в исходном формате.

Поддерживаемые локаторы:

- TXT/CSV/JSON/XML — номер строки;
- DOCX — номер абзаца либо таблица, строка и столбец;
- ODT/ODS — абзац либо таблица, строка и столбец;
- XLSX — имя листа и адрес ячейки;
- PDF — страница, номер строки и геометрические координаты.

## Правило достоверности

Автоматически извлечённое значение не перезаписывается оператором. Исправление хранится отдельной записью поверх машинного результата:

```text
машинное значение
+ ручное переопределение
+ выбранный фрагмент-доказательство
+ причина
+ пользователь и время
= актуальное значение для интерфейса и будущих отчётов
```

Это позволяет в любой момент показать исходный результат автоматики, ручное исправление и основание изменения.

## Пользовательский поток

1. Оператор открывает документ.
2. В инспекторе видит его структурный источник.
3. Нажимает `Показать источник` у поля.
4. Система выделяет соответствующий абзац, ячейку или строку PDF.
5. При необходимости оператор выбирает другой фрагмент.
6. Нажимает `Исправить`, вводит значение и причину.
7. Система сохраняет исправление отдельно и показывает отметку `Исправлено вручную`.

## Ограничения текущего контура

- PDF отображается по текстовому слою `pdftotext -bbox-layout`, без растрового изображения страницы.
- Формулы XLSX сохраняются по вычисленному значению из XML; пересчёт формул не выполняется.
- Стили DOCX и XLSX используются только как вспомогательные метаданные.
- OCR сканов остаётся отдельным адаптером следующего этапа.
