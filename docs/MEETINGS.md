# Заседания кафедры, протоколы и выписки

Контур заседаний связывает существующие планы и задачи с официальным результатом обсуждения. Он работает полностью локально и не требует LLM.

## Что настраивается один раз

В разделе **Заседания → Настройки** задаются пять параметров кафедры:

1. **Шаблон протокола заседания** — DOCX.
2. **Шаблон выписки из протокола** — DOCX.
3. **Кворум** — минимальное число присутствующих для заседания.
4. **Председатель** — выбирается из действующих сотрудников системы.
5. **Секретарь** — выбирается из действующих сотрудников системы.

DOCX-шаблоны загружаются прямо из настроек заседаний. Они регистрируются как служебные документы типа `meeting_template`, но не отправляются worker-процессу на распознавание, поэтому шаблон нельзя ошибочно импортировать как состоявшееся заседание.

У каждого шаблона должен быть отдельный абзац:

```text
{{AGENDA}}
```

Этот абзац заменяется нумерованными вопросами. Дополнительно поддерживаются маркеры:

```text
{{DOCUMENT_KIND}}
{{PROTOCOL_NUMBER}}
{{MEETING_DATE}}
{{MEETING_TITLE}}
{{CHAIRPERSON}}
{{SECRETARY}}
{{QUORUM}}
```

Оформление абзаца `{{AGENDA}}` берётся из самого DOCX и используется для сформированных строк повестки. Исходный шаблон не изменяется.

## Заседание

Для нового заседания оператор указывает только дату, номер протокола и при необходимости меняет название. Кворум, председатель, секретарь и обе версии шаблонов копируются из текущих настроек. Поэтому последующая смена шаблона не меняет уже созданное заседание.

Заседание сразу появляется в календаре как событие. Изменение даты или номера обновляет существующее календарное событие, а не создаёт новое.

## Повестка

Повестка — упорядоченный список вопросов `1…N`. Вопрос можно:

- добавить вручную;
- добавить из пункта плана;
- добавить из открытой календарной задачи.

При добавлении из источника сохраняется связь с исходной записью. Один и тот же пункт нельзя случайно включить дважды в одно заседание, но его можно рассматривать повторно на другом заседании.

Для пункта плана о статье система предлагает формулировку вида:

```text
О рассмотрении научной статьи «Подготовить научную статью …»
```

Это только детерминированное предложение. Секретарь может сразу исправить формулировку. Система не выдумывает, кто выступал и какое решение принято.

У вопроса хранятся:

- номер;
- формулировка;
- `Слушали`;
- `Обсудили`;
- `Решили`;
- ссылка на исходный пункт плана или задачу, если вопрос создан из неё.

Удаление вопроса автоматически уплотняет нумерацию. Перемещение вверх/вниз меняет номера без разрывов. В глобальный локальный поиск попадают формулировка вопроса и тексты `Слушали / Обсудили / Решили`.

Для пунктов плана интерфейс показывает обратную связь: **«Рассмотрено: протокол №… · вопрос …»**. По ней можно перейти прямо в заседание.

## Протокол

Кнопка **Сформировать протокол** создаёт DOCX по шаблону протокола и включает всю текущую повестку в исходном порядке.

Сформированный файл:

- регистрируется в общем хранилище документов;
- не отправляется повторно на распознавание протоколов;
- получает обычный локальный поиск и права рабочего пространства;
- связывается с заседанием;
- становится исходным документом нового заседания для совместимости с существующим контуром протоколов.

Если данные заседания и шаблон не изменились, повторное формирование возвращает уже созданный документ. Дубликат не создаётся.

## Выписка

Номер слева от каждого вопроса одновременно является выбором для выписки. Можно отметить любой набор, например **4** и **8**, после чего нажать **Выписка · 2**.

В DOCX попадают только выбранные вопросы, при этом сохраняются их исходные номера `4` и `8`, номер и дата исходного протокола, председатель, секретарь и кворум. Вопросы `1–3`, `5–7` в такую выписку не включаются.

Набор выбранных номеров хранится вместе со сформированным документом. Повторная генерация того же набора по неизменённым данным идемпотентна.

## Хранение и совместимость

Миграция `017_meeting_agenda_documents.sql` сохраняет уже импортированные заседания, вопросы и решения. Для новых заседаний исходный документ может отсутствовать до формирования протокола. Старые импортированные протоколы продолжают использовать прежний источник.

Связи с планом и задачами хранят идентификаторы исходных записей и понятную подпись источника. Удаление или редактирование вопроса не изменяет исходный план/задачу.

## Проверки

Контур покрывается автоматическими проверками:

- миграция существующих протоколов без потери вопросов и решений;
- настройки кафедры и снимок параметров заседания;
- вопрос из пункта плана о научной статье;
- запрет случайного дубля одного источника в одной повестке;
- плотная нумерация после удаления;
- поиск по содержимому заседания;
- выписка ровно по вопросам №4 и №8;
- идемпотентное повторное формирование DOCX;
- полный протокол по всем вопросам;
- браузерный сценарий desktop/mobile с прямой загрузкой обоих шаблонов.
