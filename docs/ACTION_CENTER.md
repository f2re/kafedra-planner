# Единый центр действий и универсальная загрузка

## Назначение

Кнопка `+ Добавить`, сочетание `Ctrl/Cmd+N` и действие `+` конкретного дня открывают один центр. Пользователь может выбрать предметное действие либо сразу передать файл, не выбирая заранее раздел и вид документа.

Центр не является второй системой форм и не создаёт параллельные предметные сущности. Его действия вызывают существующие сценарии календаря, планов, заседаний, поручений, шаблонов, учебной успеваемости, науки и проверки.

## Стабильная адаптивность

Интерфейс всегда содержит:

- три места `Рекомендуется`;
- фиксированные группы действий;
- детерминированный поиск;
- универсальную область загрузки.

Геометрия не зависит от статистики. Контекст `action.center.action` относится к `rank-only`: явный выбор человека может влиять только на порядок доступных вариантов. Автоматически выбранный маршрут документа частоту не увеличивает.

Приоритет ранжирования:

```text
явный текущий контекст и дата
→ доступность предметного сценария
→ календарный период
→ персональная частота
→ статический порядок
```

Дата, полученная от конкретного дня календаря, передаётся в форму задачи или события и не заменяется статистическим значением.

## Универсальный document intake

Загрузка использует штатный `POST /api/documents` и не обходит существующие гарантии:

1. поток сохраняется в blob-store;
2. фиксируются SHA-256, `document` и неизменяемая `document_version`;
3. создаётся идемпотентное задание обработки;
4. worker извлекает текст и структуру;
5. deterministic classifier/materializer создаёт предметный объект;
6. центр читает результат именно загруженного `documentId` и открывает точный созданный объект.

Поддерживаются форматы штатного intake: PDF, DOCX, ODT, XLSX, ODS, CSV/TXT/Markdown/JSON/XML и изображения. Старые DOC/XLS сохраняются, но при отсутствии безопасного конвертера переходят в исправимое состояние проверки, а не теряются.

## Маршруты

- план — открывается `plan.id` из extraction result;
- протокол — открывается `protocol.id`, а для ранее созданных документов допускается связанное заседание из document read-model;
- распоряжение, приказ или указ — открывается точный `directive.id`;
- ведомость успеваемости — действие `academic.import` открывает существующий импорт XLSX/ODS/CSV без второй формы;
- научный материал — открывается точный `science.id`;
- неизвестный или неоднозначный документ — остаётся в реестре и ведёт в `Проверку` либо инспектор документов.

Закрытие центра не отменяет уже принятую сервером обработку. Ошибка классификации не удаляет исходник и не требует повторной загрузки.

## Протокол и существующее заседание

Протокол автоматически объединяется только при одном из условий:

- уже существует заседание с той же `source_document_version_id` или с этой версией в сохранённом evidence;
- найдено ровно одно заседание с одновременным точным совпадением номера протокола и даты.

При объединении:

- пустые реквизиты и пустые части вопроса можно заполнить;
- заполненные отличающиеся значения не перезаписываются;
- вопрос сопоставляется по нормализованному точному названию;
- новый вопрос добавляется только при свободном номере;
- различающийся текст решения, срок, ответственный или занятый номер создаёт вопрос проверки;
- evidence каждого обработанного источника сохраняется в `evidence_json` и search fragment;
- materialization записывает точный `meetingId` в extraction result, поэтому универсальная загрузка открывает связанное заседание, а не последний элемент списка;
- повтор той же source-version не создаёт второй объект, agenda item, decision, search fragment или review item.

## Деградация

Preference-layer, локальная LLM, preview или конкретный предметный launcher не являются условием сохранения файла. При их ошибке статический каталог и обычный immutable intake остаются доступными. LLM не выбирает маршрут автоматически и не превращает предложение в подтверждённый факт.

## Проверки

Минимальный набор:

```bash
node --test tests/action-center-registry.test.mjs tests/protocol-merge.test.mjs
npx playwright test tests/browser/action-center.spec.mjs
npm run check
npm test
npm run test:browser
npm run backup:selftest
```

Browser-проверка выполняется на desktop и mobile, отдельно проверяет `prefers-reduced-motion`, точную дату дня, переход к плану, созданному конкретной загрузкой, и запуск существующей формы ведомости через `academic.import`.
