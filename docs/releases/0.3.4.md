# Kafedra Planner 0.3.4

## Главное

Версия `0.3.4` объединяет четыре законченных пользовательских сценария: визуальную настройку обычных DOCX-шаблонов заседаний, отдельную библиотеку их версий и обратимого архива, сетевой импорт сотрудников из Оформлятора с явным выбором переносимых полей и адаптивное заполнение ручных пунктов плана. Схема SQLite повышена до `30`.

## Заседания: визуальный DOCX-шаблонизатор

Оператор может загрузить обычный DOCX без специальных служебных маркеров, выбрать поля и повторяемые участки в браузере и сохранить проверяемый профиль генерации. При формировании протокола или выписки сохраняются исходные OOXML-стили, форматирование, нумерация и структура повторяемых строк/абзацев; совместимость с прежним `{{AGENDA}}` сохраняется.

## Заседания: библиотека версий шаблонов

Шаблоны протоколов и выписок теперь управляются в отдельной библиотеке. Для каждой формы видны вид документа, состояние готовности, основной статус, автор, число связанных заседаний, созданных документов и тестовых заполнений. Новая утверждённая форма добавляется следующей версией серии и не меняет уже созданные заседания.

Перед использованием шаблон можно заполнить двумя проверочными вопросами, посмотреть результат в браузере и скачать неизменяемый DOCX. Локальный PDF-preview создаётся при наличии LibreOffice, но ошибка или отсутствие LibreOffice не отменяет готовый DOCX. Архивирование показывает влияние, требует причину и — для основного шаблона — готовую замену. Исходник, профили, исторические заседания и сформированные документы не удаляются; восстановление возвращает форму в рабочий список.

Migration `029` добавляет каталог версий и идемпотентный журнал тестовых генераций без изменения прежних документов и настроек заседаний.

## Оформлятор: выбор полей сотрудников

После проверки адреса и порта Kafedra Planner читает определения полей выбранного пространства Оформлятора. ФИО переносится всегда. Для стандартных колонок локального справочника можно отдельно назначить источник для `E-mail` и `Должность`; система предлагает наиболее вероятные поля по стабильному ключу, подписи и aliases, но окончательный выбор остаётся за оператором.

Дополнительные свойства — телефон, подразделение, учёная степень и другие поля типа `person` — выбираются чекбоксами. Их значения хранятся отдельно от базовой таблицы `people` вместе с исходным `remote employee id`, ключом и подписью свойства. Повторная синхронизация обновляет ту же запись и не создаёт дубль.

Перед изменением локальных данных выбранные ключи сверяются с текущими property definitions Оформлятора. Если поле было удалено или переименовано, импорт останавливается с понятным конфликтом вместо тихой потери данных. Профили сотрудников загружаются ограниченным параллелизмом, сетевые запросы выполняются до SQLite-транзакции, а четырёхзначный код доступа по-прежнему не сохраняется.

Migration `030` добавляет только настройку сопоставления полей и значения дополнительных свойств. Обновление `29 → 30` сохраняет `people`, `docomator_integrations`, внешние связи и таблицы библиотеки заседаний.

## Ручные планы: адаптивное заполнение

Форма ручного пункта плана использует безопасные персональные значения по умолчанию для направления, режима исполнения, основного исполнителя, контролирующего и относительных дат. Статистика обучается только на явных действиях пользователя после успешного сохранения: программные подстановки сами себя не усиливают.

Сохранённые значения существующего пункта, дата перехода из календаря и руководитель исполнителя из оргструктуры имеют приоритет над learned defaults. Абсолютные даты не запоминаются — сохраняются только относительные смещения. Основной исполнитель отделён от соисполнителей, а существующий backend-контракт и идемпотентность назначения не меняются.

## Надёжность выпуска

Новые таблицы входят в acceptance digest и штатный backup/restore. Полный выпускной контур проверяет:

- последовательное обновление `28 → 29 → 30` без потери документов, сотрудников, связей Оформлятора и исторических версий шаблонов;
- visual DOCX editor, повторяемые блоки и сохранение OOXML-структуры;
- библиотеку шаблонов desktop/mobile: тест двумя вопросами, новая версия, смена основного, точная старая версия, impact, архив и восстановление;
- отсутствие rollback готового тестового DOCX при ошибке необязательного preview;
- discovery property definitions, предложения e-mail/должности, дополнительные поля и сохранение mapping до импорта;
- загрузку профилей, идемпотентный повторный импорт, обновление дополнительных значений и отказ при исчезновении выбранного remote property;
- адаптивные defaults ручного плана, приоритет доменного контекста и обучение только на явных действиях;
- существующие планы, назначения, PIN-авторизацию, ACL, lifecycle документов, отчёты и научный реестр;
- полный Debian 12 offline bundle, реальную systemd-установку, LLM-вариант, Project Control update, backup/restore и rollback.

Публикация `v0.3.4` выполняется только после успешного squash merge, зелёного post-merge CI и повторной проверки исходного SHA. GitHub Release содержит полный автономный bundle, установщик, инструкцию, пакет F2RE Project Control и SHA-256.
