# Kafedra Planner 0.4.3

## Протоколы за год

- В разделе **Заседания** можно выбрать год и загрузить сразу набор DOCX, ODT, PDF или TXT протоколов.
- Каждый файл сначала сохраняется как неизменяемая версия документа с SHA-256, затем обрабатывается независимо.
- Сводка показывает `Готово / Нужно проверить / Ошибка / Обрабатывается` и восстанавливается после перезагрузки из устойчивых данных.
- Один плохой документ не блокирует остальные успешно распознанные заседания.
- Выбранный год используется как intake context: дата из другого года создаёт вопрос проверки и не переписывается автоматически.
- Протокол без текстового слоя всё равно остаётся сохранённым источником и создаёт редактируемую карточку для ручного восстановления.

## Исправление исключений

Действие **Исправить** открывает точное заседание и исходный документ. Можно скорректировать номер, дату, название, вопрос, `Слушали`, `Обсудили`, `Решили`, ответственного и срок.

Ручная коррекция обновляет рабочие meeting/decision/calendar/search projections и закрывает только действительно устранённые review-items. Исходный machine result, locator/evidence, `document_version`, blob и SHA-256 не перезаписываются; before/after остаётся в audit/evidence history.

Повторная загрузка одного файла в тот же год идемпотентна и не создаёт второй document или meeting.

## Выпуск и обновление

Release pipeline больше не привязан к номеру версии workflow:

- обычные feature PR не запускают тяжёлый release gate;
- универсальный **Release gate** на `main` выполняет полный unit/integration regression, критический desktop/mobile browser и recovery checks;
- publisher не ждёт и не перезапускает другие workflows и не повторяет уже доказанные unit/Playwright suites;
- полный offline bundle собирается один раз;
- тот же artifact проходит Debian 12 systemd clean install, repeated update, legacy upgrade и `forced-core-rollback`;
- Project Control package строится из того же проверенного archive;
- в GitHub Release публикуются ровно семь проверенных assets.

SQLite schema остаётся **31**. Новой migration нет.

## Обновление существующей установки

Скачайте все файлы `v0.4.3` в обычную читаемую папку пользователя, проверьте `SHA256SUMS` и запустите:

```bash
sudo KAFEDRA_APT_MODE=bundle ./install-kafedra-planner.sh
```

Исходная пользовательская папка не обязана принадлежать root. Installer создаёт backup, использует приватный root staging, атомарно переключает `/opt/kafedra-planner/current` и автоматически возвращает прежнее состояние при post-update failure.

После установки:

```bash
cat /opt/kafedra-planner/current/VERSION
sudo /opt/kafedra-planner/current/scripts/offline/doctor.sh
```

Ожидаемая версия: `0.4.3`.

## Совместимость

- Данные и schema 31 из `0.4.2` обновляются без destructive reset.
- Прямая интеграция с Оформлятором из `0.4.2` сохраняется без изменения контракта.
