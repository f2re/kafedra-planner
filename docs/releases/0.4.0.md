# Kafedra Planner 0.4.0

## Главное

Версия `0.4.0` добавляет законченный автономный контур учёта успеваемости: оператор загружает ведомость XLSX, ODS или CSV, система сохраняет неизменяемый исходник, определяет структуру таблицы, создаёт актуальную ведомость учебной группы и формирует доказуемую сводку по дисциплинам. Схема SQLite повышена с `30` до `31` одной добавочной миграцией.

Релиз также включает единый центр действий из актуального `main`: академическая ведомость запускается через фиксированную группу «Учебный процесс» без дублирования предметной формы и без изменения геометрии интерфейса.

## Ведомости учебных групп

Исходный файл сначала проходит обычный document intake и регистрируется как immutable `document_version` с SHA-256. Только после сохранения источника система анализирует листы, строку заголовков, колонку ФИО и колонки дисциплин.

Группа, учебный год и семестр могут быть взяты из точной ячейки либо введены вручную. Для найденного значения сохраняются документ, версия, лист, строка, колонка, адрес ячейки, исходный текст и правило нормализации. Автоматическое предложение остаётся исправимым и не выдаётся за подтверждённый факт.

Каждая оценка хранит исходное значение и локатор. Значения `5`, `4`, `3`, `2` и документированные текстовые эквиваленты распределяются по категориям «отлично», «хорошо», «удовлетворительно» и «неудовлетворительно». Явная неаттестация учитывается отдельно. Пустая ячейка и прочерк не превращаются в неаттестацию. Неизвестное непустое значение сохраняется как требующее проверки и исключается из среднего балла.

## Сводка и доказательства

Для каждой дисциплины показываются:

- число записанных значений;
- количество оценок по категориям;
- число неаттестаций;
- число значений, требующих проверки;
- средний балл только по числовым оценкам `2–5`.

Средний балл округляется до двух знаков, а операторский интерфейс и CSV используют десятичную запятую. Строка дисциплины раскрывается до студентов, исходных значений и точных ячеек ведомости.

Сводка по выбранным актуальным группам рассчитывается непосредственно из сохранённых оценок. Она не хранится второй таблицей и поэтому не может разойтись с первичными фактами. Доступны CSV, JSON и `sources.json` с идентификаторами источников и локаторами.

## Версии, частичный успех и архив

Для одной группы и учебного периода существует одна актуальная успешно обработанная ведомость. Новый успешный импорт переводит прежнюю версию в историю. Ошибка новой версии не снимает старую актуальную ведомость.

Повтор запроса с тем же idempotency key не создаёт дубликаты импортов, студентов, дисциплин или оценок. Ошибка одной строки или ячейки не блокирует остальные данные. Архивирование и восстановление обратимы; исходный файл, SHA-256, исторические версии и evidence не удаляются.

## Интерфейс

На desktop дерево «учебный год → семестр → группа» расположено рядом со сводкой. На мобильном тот же предметный сценарий представлен последовательными секциями без обязательной горизонтальной навигации. Основное действие — «Загрузить ведомость»; экспорт и lifecycle-действия вторичны.

`academic.import` добавлен в единый Action Center как `rank-only`: статистика может влиять только на безопасное ранжирование рекомендации. Импорт, выбор ячеек, ручные значения, архив, восстановление, ACL и свободный текст не обучаются.

При `prefers-reduced-motion: reduce` академические переходы имеют нулевую длительность; импорт, расчёт, ошибки и evidence полностью понятны без анимации.

## Миграция и восстановление

Migration `031_academic_performance.sql` только добавляет таблицы групп, учебных периодов, студентов, составов, дисциплин, импортов, привязок метаполей, оценок и ошибок. Миграции `001–030` не изменены.

Проверки выпуска подтверждают:

- чистую установку схемы `31`;
- обновление реальной базы `30 → 31`;
- повторный безопасный запуск миграций;
- `PRAGMA quick_check` и `PRAGMA foreign_key_check`;
- создание и проверку резервной копии перед миграцией;
- восстановление базы и blob-файлов;
- rollback после искусственной ошибки обновления;
- включение академических таблиц в acceptance digest и backup/restore evidence.

## Автономный выпуск

Основной функционал работает без обязательного Интернета, Docker, CDN, облачного сервиса или LLM. Релиз остаётся release candidate до отдельной целевой приёмки на реальных Astra Linux и Debian установках.

Публикация `v0.4.0` выполняется только с подтверждённого commit в `main` после полного CI и post-merge CI. GitHub Release содержит автономный Debian/Astra bundle, его SHA-256, установщик, `README-INSTALL`, пакет F2RE Project Control, digest пакета и общий `SHA256SUMS`. Старые теги и assets не перемещаются и не заменяются.
