# Kafedra Planner 0.3.2

## Главное

Patch release добавляет автоматическое создание рабочих поручений из исполнителей,
указанных в импортируемом плане кафедры, и публикует новый проверяемый full offline
bundle поверх актуального `main`.

## Планы и исполнители

- ФИО из строк плана сопоставляются со справочником сотрудников без обязательной
  ручной настройки каждого пункта;
- при однозначном сопоставлении для пункта автоматически создаётся поручение и
  назначается исполнитель;
- неоднозначные и отсутствующие совпадения не угадываются: исходное значение
  сохраняется, а оператор получает понятное состояние для проверки;
- автоматическое назначение встроено в существующий контур `план → пункт →
  поручение → календарь → отчёт`, без создания параллельной сущности;
- повторная обработка остаётся идемпотентной и не удаляет существующую работу.

## Уже включённый lifecycle документов и планов

Релиз наследует реализованный в `0.3.1` безопасный lifecycle документов и планов:
редактирование метаданных, impact preview, архивирование, восстановление и явную
связь с заменяющим объектом. Исходные версии документов, evidence, пункты плана,
календарные записи и завершённые факты не перепривязываются молча.

## Проверка и поставка

Перед публикацией release pipeline требует успешные quality, migration/backup и
browser gates, включая desktop/mobile сценарии планов, lifecycle и автоматических
назначений. После этого повторно выполняются unit/smoke/backup проверки, собирается
полный автономный Debian/Astra bundle и пакет F2RE Project Control.

GitHub Release содержит:

- `kafedra-planner-0.3.2*.tar.gz` — полный offline bundle;
- `.sha256` для bundle;
- `install-kafedra-planner.sh`;
- `README-INSTALL.txt`;
- `kafedra-planner-0.3.2-project-control.f2re.zip` и его SHA-256;
- общий `SHA256SUMS`.

Проверка после скачивания:

```bash
sha256sum -c --strict SHA256SUMS
sudo KAFEDRA_APT_MODE=bundle ./install-kafedra-planner.sh
```

Установщик использует штатную транзакционную схему обновления: pre-update backup,
проверку manifest/integrity, последовательные миграции, health/doctor и
автоматический rollback при неуспешном запуске.
