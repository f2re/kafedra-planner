# Kafedra Planner 0.4.5

Выпуск завершает доработку заседаний и массового импорта протоколов после `v0.4.4`. Основание описания — изменения #348, #350 и #351. SQLite schema остаётся `31`; новые migrations и зависимости исполнения не добавляются.

## Распознавание протоколов

Отдельная повестка сопоставляется с блоками «По первому / второму / третьему вопросу» и числовыми ссылками. Поддерживаются варианты обозначений разделов, регистр, пробелы и ограниченные опечатки структурных меток. Нумерованные подпункты остаются внутри решения; подписи отделяются. Нераспределённые фрагменты и неоднозначные сроки не теряются и требуют проверки.

Дата извлекается из шапки каждого загруженного файла. Номер, дата или год образца не зашиты в обработчик. При неполной или некорректной дате, например дне «00», сохраняется исходная строка; дата решения, учебный год и текущая дата не подставляются вместо неё. Остальные вопросы документа доступны сразу.

## Массовое исправление и повтор

Все выбранные файлы появляются в очереди; ошибка одного не блокирует остальные. Есть фильтр исключений, выбор документов и общая форма реквизитов с текстом шапки и ссылкой на исходник. Сохраняются только изменённые строки; конфликт с более новой правкой не перезаписывает её. Ошибочные значения остаются в форме.

Редактор формата распознавания позволяет указать дополнительные обозначения разделов, проверить результат на образце, сохранить новую версию и повторно обработать выбранные документы. Повтор использует тот же immutable source и сохраняет предыдущие результаты, ручные исправления, перенесённые и удалённые вопросы. История машинных изменений содержит значения до и после; ошибка записи откатывает предметную операцию.

## Удаление неудачных загрузок

Неотправленный файл можно убрать из списка. Сохранённый файл можно перенести **В архив** непосредственно из очереди и **Восстановить** из архива. Повторная загрузка уже известного архивного файла не создаёт второй экземпляр и не восстанавливает его без явного действия.

Архивирование файла не удаляет созданное заседание, решения или ручные правки: они могут использоваться другими документами. Неудачные вопросы удаляются в существующем редакторе заседания; повтор распознавания не создаёт их заново. Физическое удаление исходников и истории не выполняется.

## Заседания и документы

Перенос вопроса между заседаниями устойчив к повторным запросам, сохраняет источники и связи с планом. Исправленная дата согласована с годовой навигацией. DOCX-протокол включает все решения; ранее сформированные версии остаются неизменяемыми.

## Установка и проверка

Используется прежний универсальный Release workflow: проверка кода и данных, критические браузерные сценарии, резервное копирование, одна сборка offline bundle и проверка этого же архива через install/update/rollback. Публикуется тот же проверенный архив с SHA-256 и пакетом Project Control.

Для обновления скачайте файлы одного выпуска в обычную пользовательскую папку и выполните:

```bash
sudo KAFEDRA_APT_MODE=bundle ./install-kafedra-planner.sh
```

После обновления перезагрузите страницу браузера. Установленную версию можно проверить командой `cat /opt/kafedra-planner/current/VERSION`.

Эксплуатационная проверка реальных документов на целевой Astra Linux/Debian проводится после установки этого выпуска. Автоматические проверки её не подменяют; stable-приёмка #27 остаётся отдельной.
