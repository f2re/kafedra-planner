# Kafedra Planner 0.4.4

## Меньше ручной работы

- Календарная запись из конкретного дня открывается короткой формой: дата уже известна из контекста, редкие параметры собраны под **Дополнительно**.
- `Календарь → план` больше не заставляет повторять дату и лишний промежуточный экран: 0 планов → создать и продолжить, 1 план → сразу пункт, несколько → выбрать план и продолжить.
- Новое заседание можно начать с даты и номера протокола; настройка выпуска и шаблонов не блокирует рабочую повестку.
- Периодическая задача имеет прямые действия **Выполнено / Вернуть в работу**. Файл, справка и отчёт остаются необязательными.
- Поиск открывает точный рабочий объект и после возврата восстанавливает запрос, фильтры, прокрутку и фокус.

## OCR, загрузка и доказательства

- Постраничный OCR сохраняет абсолютные номера страниц, coverage, confidence/геометрию и точные locators.
- Сбой отдельной страницы сохраняет успешно распознанные страницы; partial OCR не выдаётся за полный.
- Текстовая первая страница не отключает OCR следующих сканированных страниц.
- Повторная обработка использует ту же immutable `document_version`, создаёт новый `extraction_run` и не переписывает старый machine result.
- Ручное рабочее значение имеет приоритет; новое расхождение остаётся review-by-exception с evidence.
- Upload UI считает `Готово / Ошибка / Обрабатывается` только по подтверждённым ответам сервера и честно показывает смешанный batch.

## Протоколы и адаптация

- Стабильный локальный формат кафедрального протокола может использовать дополнительный детерминированный profile layer поверх базового `department_protocol` parser.
- Profile-поля сохраняются с `document_version`, extraction run и locator; неизвестное поле не превращается автоматически в подтверждённый предметный факт.
- Ошибка одного profile-template локальна и не уничтожает успешный базовый разбор.
- Реальная приёмка профиля на двух обезличенных повторяющихся протоколах остаётся в issue #326; synthetic fixtures не считаются заменой этой проверки.
- Adaptive defaults теперь имеют явные learning controls, reset и безопасные pins. Saved/explicit/domain-derived значения сильнее статистических подсказок, `never-learn` действия не обучаются.

## Установка и offline bundle

Для целевой машины по-прежнему достаточно скачать canonical release files в обычную читаемую пользовательскую папку и запустить:

```bash
sudo KAFEDRA_APT_MODE=bundle ./install-kafedra-planner.sh
```

Full bundle содержит managed Node.js/CPython и air-gap closure для `unzip`, Poppler, Tesseract `rus+eng`, LibreOffice и шрифтов. Системные пакеты не фиксируются к конкретной target-версии: устанавливаются только отсутствующие возможности, без принудительного upgrade/downgrade/remove и без автоматического `apt --fix-broken`.

До переключения `/opt/kafedra-planner/current` выполняются strict full preflight и реальный OCR self-test:

```text
ocr.py doctor --languages rus+eng --self-test
```

Если Tesseract/Poppler/LibreOffice не готовы, новый release не активируется. Исходная пользовательская папка не переоформляется на root.

## Выпуск и проверки

- Обычный pull request проходит полный project CI один раз; после merge запускается только короткий smoke.
- GRACE не повторяет project tests и автоматически не запускается второй раз после merge.
- Один version-neutral workflow `Release` работает только с exact текущим `main`.
- Full offline bundle собирается ровно один раз.
- Тот же archive проходит SHA-256, Debian 12 systemd clean install, repeated update и forced rollback; Project Control формируется из него же.
- Публикация загружает только этот проверенный archive и его canonical metadata/assets без пересборки.

SQLite schema остаётся **31**. Новой migration в `0.4.4` нет. Production по-прежнему не требует Docker, обязательного Интернета, облака или LLM.
