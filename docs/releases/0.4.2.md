# Kafedra Planner 0.4.2

## Главное

`0.4.2` — patch-релиз прямой интеграции с Оформлятором и надёжного обновления установленного интерфейса. SQLite schema остаётся `31`; destructive reset, изменение применённых migrations и обязательная внешняя зависимость не вводятся.

## Изменения

- В **Настройки → Структура кафедры → Импорт из Оформлятора** теперь вставляется один полный адрес: URL из браузера, hostname, IPv4 или IPv6. Протокол и порт не требуется разносить по отдельным полям.
- Известные окончания `/api/v1`, `/healthz`, `/readyz` и `/api/v1/system/*` нормализуются до origin; логин, пароль, query, fragment и чужой path отклоняются до сетевого запроса.
- Проверка совместима с актуальным Docomator: `/readyz` принимает `status: ok` и legacy `ready`, затем проверяются пространства, группы, сотрудники и доступные свойства.
- DNS, отказ порта, timeout, TLS, чужой HTTP-сервис, неготовая база и несовместимый API имеют отдельные безопасные сообщения.
- Импорт сотрудников остаётся идемпотентным по remote employee id; ошибка одной записи учитывается как partial success и не отменяет остальные записи.
- Mapping полей сохраняется перед импортом без гонки с первоначальной загрузкой настроек; четырёхзначный код доступа не сохраняется.
- Установочный wrapper можно запускать из обычного пользовательского каталога. Исходный архив не меняет владельца: root используется только для приватного staging, системных каталогов, backup, переключения release и systemd.
- После обновления активный release проверяет обязательные UI-файлы, а статические файлы выдаются с `Cache-Control: no-store`, поэтому старый нефингерпринтованный сайт не остаётся в browser/proxy cache.
- Документированы единые команды перезапуска, статуса и журнала API/worker.

## Перезапуск служб

```bash
sudo systemctl restart kafedra-planner-api.service kafedra-planner-worker.service
sudo systemctl status --no-pager -l kafedra-planner-api.service kafedra-planner-worker.service
sudo journalctl -u kafedra-planner-api.service -u kafedra-planner-worker.service -n 100 --no-pager
```

Служба `kafedra-planner-llama.service` перезапускается отдельно только при использовании управляемой локальной LLM.

## Установка и обновление

Скачайте в один обычный каталог архив, его `.sha256`, `install-kafedra-planner.sh`, `README-INSTALL.txt` и `SHA256SUMS`. Проверка выполняется до распаковки. Wrapper сам получает необходимые root-права через `sudo`, извлекает bundle в приватный staging, создаёт и проверяет резервную копию, атомарно переключает `/opt/kafedra-planner/current` и выполняет rollback при ошибке.

Данные, blobs, конфигурация и PIN сохраняются. Установленный исполняемый release остаётся `root:root` и недоступен для записи service user; `/var/lib/kafedra-planner` остаётся во владении `kafedra-planner:kafedra-planner`.
