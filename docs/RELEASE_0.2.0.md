# Выпуск 0.2.0

## Назначение выпуска

Версия 0.2.0 завершает два связанных эксплуатационных контура:

1. историческая организационная структура;
2. полный управляемый цикл научной деятельности.

Основной функционал работает локально без LLM и Интернета. Исходные документы, версии, evidence и история корректировок сохраняются.

## Новые пользовательские сценарии

### Организационная структура

- подразделения и иерархия с периодами действия;
- отдельный справочник должностей;
- основные и дополнительные назначения сотрудников;
- руководитель на период;
- просмотр структуры на произвольную дату;
- запрет пересекающихся основных назначений и циклов руководителей;
- аудируемое исправление периода;
- научная аффилиация автора на дату публикации.

### Научная карточка

- ручное исправление отдельно от извлечённого значения;
- обязательная причина и история ревизий;
- этапы: замысел, подготовка, подано, доработка, принято, опубликовано, отклонено, архив;
- следующее действие, срок и подтверждающий документ;
- атомарная связь с пунктом плана и поручением.

### Массовый импорт

- CSV, JSON, XLSX и ODS;
- предварительное сопоставление колонок;
- частичный успех по строкам;
- DOI/title-year дедупликация;
- обновление существующей карточки только по явному выбору;
- идемпотентный журнал запусков.

### Отчёты

- фильтры по периоду, сотруднику, историческому подразделению, виду, этапу и классификации;
- выбор полей;
- CSV и DOCX;
- пользовательский DOCX-образец;
- доказательства по каждой строке;
- идемпотентная генерация и отдельный журнал.

## Миграции

Версия включает схемы 20–25:

- `020_organization_history.sql`;
- `021_science_lifecycle.sql`;
- `022_science_manual_overrides.sql`;
- `023_science_bulk_import.sql`;
- `024_science_reports.sql`.
- `025_directive_report_archive.sql` — материалы отчётности распоряжений и их календарная проекция.

Миграции добавляют новые таблицы и поля, не удаляя документы, планы, поручения и научные карточки. Текущие `people.position` и `people.manager_id` переносятся в исторические назначения и остаются совместимой проекцией текущего основного назначения.

## Обновление

Перед обновлением:

1. остановить запись либо перевести систему в штатный режим обслуживания;
2. создать проверенную резервную копию;
3. выполнить `target-acceptance-020 collect --full`;
4. установить release;
5. дождаться миграций и запуска API/worker;
6. повторить акт;
7. сравнить акты командой `target-acceptance-020 compare`.

Пример:

```bash
node scripts/target-acceptance-020.mjs collect --full --output before-0.2.0.json
# штатное обновление
node scripts/target-acceptance-020.mjs collect --full --output after-0.2.0.json
node scripts/target-acceptance-020.mjs compare before-0.2.0.json after-0.2.0.json
```

Код возврата сравнения:

- `0` — устойчивые данные совпадают;
- `2` — обнаружено различие;
- `1` — акт неполон или команда завершилась ошибкой.

## Откат

При неуспешном health-check штатный update-процесс возвращает предыдущий release. База и blob-хранилище не заменяются пустыми каталогами. Если миграция уже применена, старая версия не должна запускаться поверх новой схемы без поддержанного downgrade; восстановление выполняется из проверенной резервной копии в отдельный каталог.

## Новые устойчивые таблицы

Акт 0.2.0 вычисляет логические digest для:

- `organizational_units`;
- `organization_positions`;
- `person_appointments`;
- `scientific_author_affiliations`;
- `scientific_item_revisions`;
- `scientific_lifecycle_events`;
- `scientific_item_plan_links`;
- `scientific_item_manual_overrides`;
- `science_import_runs`;
- `science_import_rows`;
- `science_report_runs`.

Изменение любой из этих таблиц между актами отражается в сравнении.

## Автоматическая приёмка

Обязательный job `release-gate` требует успешного завершения:

- `npm run check`;
- полного `npm test`;
- smoke;
- миграций 19 → 24;
- backup/restore и target acceptance;
- Playwright desktop/mobile для оргструктуры, жизненного цикла, массового импорта и научных отчётов.

Нельзя сливать релиз при pending, failure, cancelled или неожиданном skipped обязательного job.
