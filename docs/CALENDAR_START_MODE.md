# Стартовый режим календаря

## Пользовательский контракт

В настройках пользователь выбирает один стартовый режим:

- `Автоматически` — разрешён безопасный обучаемый выбор `calendar.mode`;
- `Месяц`;
- `Неделя`;
- `Задачи`.

Явно выбранные `Месяц`, `Неделя` и `Задачи` имеют приоритет над статистикой использования. Обычное переключение сегментов календаря меняет текущий сеанс и может обучать `calendar.mode`, но не изменяет постоянную настройку.

## Приоритет при открытии

```text
явная настройка month/week/tasks
        ↓
learned calendar.mode, только для auto
        ↓
старый kafedra-calendar-mode как совместимый fallback
        ↓
month
```

Программное применение стартового режима не считается пользовательским выбором.

## Хранение

Для авторизованного аккаунта настройка сохраняется сервером под зарезервированным контекстом `settings.calendar.start_mode`. Физически используется уже существующее `ui_choice_preferences`, но строка настройки имеет фиксированный `interaction_id=explicit`, не входит в allowlist обучаемых ключей и никогда не участвует в ранжировании. Источник истины для стартового режима поэтому отделён от статистики `calendar.mode` на уровне service/API.

При отключённой авторизации используется локальный ключ `kafedra-calendar-start-mode-v1`. Старый `kafedra-calendar-mode` не превращается в явную настройку: он остаётся только совместимым fallback режима `Автоматически`, поэтому обновление не меняет привычный экран неожиданно.

## API

- `GET /api/ui-settings/calendar-start` — прочитать настройку текущего аккаунта;
- `PUT /api/ui-settings/calendar-start` — сохранить `{ "calendarStartMode": "auto|month|week|tasks" }`.

API доступен только для аккаунта текущей сессии. В режиме без авторизации браузер не вызывает его и использует локальный fallback.

## Отказоустойчивость

Ошибка чтения настройки не блокирует календарь: используется `Автоматически` и существующий безопасный fallback. Ошибка записи оставляет текущий режим и введённый выбор на экране. Новых миграций для этого изменения нет, поэтому параллельные миграции `020–024` из организационно-научного контура не конфликтуют с #84.
