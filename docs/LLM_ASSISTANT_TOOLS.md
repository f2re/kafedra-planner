# Прикладной модуль «Ассистент кафедры»

Модуль вспомогательных аналитических микро-задач на базе LLM (локальной или удалённой) для Кафедра-планера.

## Назначение

Инструмент ускоряет рутинную обработку неструктурированных фрагментов документов, проверку полноты данных и поиск по архиву без усложнения бизнес-модели приложения:

1. **Анализ текста из буфера (Ad-hoc Text Processing)**:
   * Пользователь вставляет текст (из протокола, письма, проекта отчёта, скана).
   * Модель извлекает упомянутые объекты (поручения со сроками, публикации, персон, протоколы).
   * Вывод: интерактивная таблица с возможностью редактирования ячеек прямо в браузере и копирования в буфер обмена.
2. **Поиск пропусков и устранение ошибок (Gap & Error Repair)**:
   * Пользователь или оператор передаёт фрагмент заседания, протокол или сообщение об ошибке.
   * Модель выявляет недостающие даты, пропущенные номера пунктов повестки, отсутствующих докладчиков и ответственных.
   * Каждое исправление сопровождается точной цитатой-обоснованием (`sourceQuote`), проверенной по исходному тексту, и конкретной рекомендацией оператору.
3. **Поиск по архиву заседаний (Archive Natural Language Query)**:
   * Естественный запрос (например: «Где обсуждалась статья о влажности почв?»).
   * Сервер выполняет полнотекстовый поиск SQLite FTS5 с фильтрацией по правам доступа (ACL).
   * Модель сопоставляет кандидатов, выделяет номера заседаний, протоколов, вопросов и точные цитаты.
4. **Формулы для LibreOffice Calc и Excel**:
   * Пользователь описывает расчёт («как подтянуть должность по ФИО через ВПР», «подсчёт часов преподавателя за семестр»).
   * Модель возвращает готовую формулу с русской локализацией функций (`ВПР`, `СУММЕСЛИМН`) и точкой с запятой `;` в качестве разделителя, а также краткую инструкцию.

## Интерфейс и доступ

* **Кнопка в шапке**: `✨ Ассистент` рядом с глобальным поиском.
* **Горячая клавиша**: `Alt + A` открывает выдвижную боковую панель (Drawer) поверх любого раздела без потери контекста.
* **Быстрый запуск**: `Ctrl + Enter` в поле ввода.
* **Закрытие**: `Esc` или клик по фону.
* **Индикатор связи и настройки**: статус в шапке панели показывает реальное состояние подключения (`● В сети (42 мс)`, `● Недоступен`, `○ Выключен`). Кнопка `⚙` открывает панель настройки параметров подключения (адрес сервера, модель, ключ).

## Умный экспорт и редактирование

* **Инлайн-правка ячеек**: кликните любую ячейку в таблице результатов, чтобы скорректировать распознанные данные до экспорта.
* **Кнопка «📋 Скопировать в Excel / Calc»**: помещает в буфер обмена формат `text/tab-separated-values` (TSV) и `text/html`. При вставке (`Ctrl + V`) в LibreOffice Calc или MS Excel данные раскладываются строго по столбцам и строкам без смещений.
* **Сохранность черновиков и история**:
  * Черновик автоматически сохраняется в `sessionStorage` по мере набора.
  * История последних 15 выполненных запросов сохраняется в `localStorage` браузера с возможностью быстрого восстановления.

## Адаптивность и доступность

* **Вместимость**: таблица результатов снабжена горизонтальной прокруткой и зафиксированной шапкой для комфортного чтения больших наборов данных.
* **Мобильные устройства**: при ширине экрана менее 640px панель занимает всю ширину экрана с увеличенными сенсорными целями (не менее 44px) для удобного управления пальцем.
* **Доступность**: диалоговые окна поддерживают фокус, клавиатурную навигацию и директиву `prefers-reduced-motion` для пользователей, чувствительных к анимации.

## Экономия токенов и безопасность

* **Санитизация**: перед отправкой в модель текст очищается от колонтитулов, пустых строк и артефактов OCR (экономия 25–40% токенов).
* **Кэширование по SHA-256**: повторный запрос с тем же текстом и задачей возвращается мгновенно (0 токенов, 0 мс).
* **Отмена генерации**: кнопка `«Отмена»` прерывает сетевой запрос через `AbortController`, освобождая ресурсы сервера модели.
* **Автономия**: при выключенном LLM ассистент сообщает о выключенном режиме, а все остальные функции системы работают штатно.

## API и сетевые контракты

### Базовое управление подключением
* `GET /api/assistant/status` — возвращает текущее состояние подключения `{ ok, enabled, configured, endpoint, model, status, latencyMs, models }`.
* `POST /api/assistant/test-connection` — принимает `{ endpoint, model, apiKey }` и выполняет проверку связи в реальном времени.
* `POST /api/assistant/config` — принимает `{ enabled, endpoint, model, apiKey }`, сохраняет настройки в `data/llm-settings.json` и обновляет активную конфигурацию.

### Синхронная и потоковая обработка
* `POST /api/assistant/process` — синхронное выполнение задачи. Принимает `{ task, text, query, promptId, stream: false }` (`table-extract`, `gap-repair`, `formula-calc`, `archive-query`, `compliance-check`, `template-analysis`, `agenda-generate`) и возвращает структурированный JSON `{ ok, task, result, cached, latencyMs, usage }`.
* `POST /api/assistant/stream` — потоковая передача результатов и хода рассуждений модели (Server-Sent Events).
  - Заголовки ответа: `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`.
  - Прерывание: закрытие HTTP-соединения клиентом или вызов `AbortSignal` мгновенно прерывает запрос к серверу LLM.
  - Потоковые события (SSE):
    - `event: stage` — текущий этап обработки (`{"stage": "Подготовка запроса..."}`).
    - `event: thinking` — дельта хода мыслей модели из `delta.reasoning_content` или `<think>...</think>` (`{"text": "Анализирую пункты повестки..."}`).
    - `event: token` — дельта результирующего текста (`{"text": "Постановили: утвердить..."}`).
    - `event: telemetry` — промежуточные метрики (`{"completionTokens": 142, "tokensPerSec": 38.5, "elapsedMs": 3680, "ttftMs": 420}`).
    - `event: done` — итоговый структурированный результат (`{"ok": true, "task": "...", "result": {...}, "telemetry": {...}, "thinking": "..."}`).
    - `event: error` — ошибка инференса (`{"ok": false, "error": "Текст ошибки"}`).

### Библиотека промптов и специализированные агенты
* `GET /api/assistant/prompts` — список встроенных и пользовательских промптов `{ ok: true, prompts: [...] }`.
* `POST /api/assistant/prompts` — создание или обновление избранного промпта `{ id, title, role, systemPrompt, userTemplate, isDefault, category }`.
* `DELETE /api/assistant/prompts/:id` — удаление пользовательского промпта.
* `GET /api/assistant/prompts/export` — выгрузка библиотеки промптов в переносимый JSON-файл.
* `POST /api/assistant/prompts/import` — импорт коллекции промптов с валидацией схемы.

### Семантический анализ и шаблоны
* `GET /api/assistant/semantic-graph` — построение графа смысловых связей между документами кафедры. Возвращает `{ nodes: [...], links: [...], clusters: [...] }`.
* `POST /api/assistant/analyze-template` — выявление заменяемых полей в тексте протокола/документа. Принимает `{ text }`, возвращает структуру `{ ok: true, fields: [{ id, name, type, defaultValue, occurrences, required }] }`.
* `POST /api/assistant/agenda-generate` — подготовка проекта повестки заседания на основе планов и контекста кафедры.
* `GET /api/assistant/search-meetings` — гибридный семантический и FTS5-поиск по протоколам заседаний.

### Мониторинг сетевых и локальных папок
* `GET /api/directory-watch/status` — состояние фоновой службы синхронизации каталогов.
* `POST /api/directory-watch/folders` — добавление отслеживаемой папки (локальный путь или смонтированный сетевой ресурс SMB/NFS).
* `POST /api/directory-watch/sync-now` — принудительный запуск сканирования и версионирования изменённых документов.

## 7. Локальный RAG и переиндексация документов для ИИ

### Архитектура поиска документов
Удалённый или локальный LLM-сервер (например `llama-server`) выполняет **только инференс** по API `/v1/chat/completions`. Сервер модели **не имеет прямого доступа** к файловой системе или SQLite-базе данных Кафедра-планнера.

Поиск документов устроен по архитектуре RAG (Retrieval-Augmented Generation):
1. **Локальный полнотекстовый поиск**: При запросе оператора в ассистенте («Архивный запрос», «Анализ протокола», «Проверка регламентов») локальный сервер `kafedra-planner` выполняет полнотекстовый поиск в локальной SQLite FTS5 (`search_fragments` и `search_fts`).
2. **Контекстное сопоставление**: Поиск использует строгое AND-соответствие ключевых слов с автоматическим fallback на OR-поиск с BM25-ранжированием при разговорных запросах, а также подтягивание недавних документов кафедры при отсутствии точных совпадений.
3. **Формирование промпта**: Найденные проверенные фрагменты документов (выдержки, номера протоколов, даты, реквизиты) вставляются в поле `candidates` входного JSON-промпта.
4. **Генерация ответа**: Модель анализирует переданный контекст и формирует точный структурированный ответ с подтверждёнными цитатами.

### Переиндексация и актуализация
Для гарантированного включения всех документов, протоколов, планов, распоряжений и научных материалов в поиск реализованы:
* **API переиндексации**: `POST /api/search/reindex` — очищает и заново индексирует все протоколы, решения, файлы документов, планы, пункты планов, распоряжения, поручения и научные работы.
* **CLI-скрипт**: `npm run search:reindex` (`node scripts/reindex-search.mjs`) — выполняет полную переиндексацию из терминала без остановки сервера.
* **Интерфейс**: Кнопка `[🔄 Переиндексировать всё]` в панели фильтров поиска и кнопка `[🔄 Индексация базы]` в настройках панели ассистента.
* **Автоматическая доиндексация**: Функция `ensureSearchIndexUpToDate` автоматически проверяет наличие неиндексированных документов и фрагментов перед каждым обращением ассистента к базе.
