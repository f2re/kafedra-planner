# ИИ-ассистент: результат, источники и история

Статус: feature scope issue #372. Базовая версия 0.4.12, baseline schema 31, новая миграция 032. Разработка не означает выпущенный релиз.

## Сквозной сценарий

1. Оператор открывает существующую панель ассистента, выбирает задачу и вводит запрос.
2. Сервер ищет кандидатов в существующем FTS5/семантическом индексе, проверяет разрешения и передаёт ограниченные фрагменты необязательной локальной LLM. При отсутствии модели штатный поиск и документы остаются доступны.
3. Ответ в процессе генерации отображается потоково; по завершении известные JSON-типы показываются таблицами, отчётами, формулами и карточками. Неструктурированный ответ показывается безопасными блоками текста, списками, заголовками и кодом, без выполнения HTML.
4. Под ответом — найденные сервером материалы. Доступны «Карточка документа», «Открыть оригинал», «Предпросмотр» (только при готовой версии) и «Скачать». Ни один documentId, придуманный моделью, не становится ссылкой на файл.
5. Завершённый или неудачный запрос сохраняется в SQLite; если сохранение не удалось, интерфейс явно предупреждает. В «Истории» можно просмотреть ответ повторно без повторной генерации, искать по уже загруженной странице, листать все записи, удалить отдельную запись или очистить историю своего аккаунта.

## Хранение

Миграция `032_assistant_history.sql` добавляет `assistant_runs`: `workspace_id`, `owner_key`, `task`, `prompt_text`, `status`, `result_json`, `raw_response`, `source_refs_json`, `error_message`, `duration_ms`, `created_at`. Исходные `file_blobs` и `document_versions` не модифицируются. Индекс по владельцу и дате обеспечивает стабильную пагинацию. Авторитетная история хранится в базе и включена в stable logical digest; она входит в резервное копирование и восстановление вместе со всей SQLite.

Модельный ход рассуждений, приватные ключи и пользовательские секреты из настроек подключения не сохраняются в истории. Сырые ответы и структурированные результаты обрезаются по объёмным ограничениям. Ранее существовавшие записи в `localStorage` не удаляются автоматически и не привязываются к текущему аккаунту: у них не было признака владельца.

## Договор API

- `POST /api/assistant/process` — добавлены `runId`, `historySaved` и `sources` к существующему ответу.
- `POST /api/assistant/stream` — событие `done` содержит те же поля, событие `error` отражает неуспешную генерацию.
- `GET /api/assistant/history?limit=30&cursor=...` — `{items,nextCursor}`, только текущий владелец/рабочее пространство.
- `GET /api/assistant/history/:runId` — объект `entry` для повторного просмотра.
- `DELETE /api/assistant/history/:runId` и `DELETE /api/assistant/history` — явное удаление оператором своей истории.
- `GET /api/documents/:id/content?variant=original|preview&versionId=...&download=1` — неизменяемая версия, обычный ACL и workspace scope; `download=1` принудительно отдаёт attachment.

`sources` вычисляет только сервер из валидных поисковых кандидатов. У каждого источника есть `kind`, `id`, при наличии `documentId`, `versionId`, `title`, `snippet`, `previewAvailable`. Сохранённая запись перепроверяется при каждом чтении: если доступ хотя бы к одному использованному источнику отозван, текст результата и запроса скрывается целиком.

## Ошибки и отказоустойчивость

Недоступная LLM, некорректный JSON, отмена пользователем, ошибки сервера и БД должны иметь различимые состояния. Нет успешного результата — нет утверждения, что задача выполнена. Сбой сохранения истории не должен уничтожать уже полученный ответ. Оригиналы остаются доступны через привычный раздел «Документы».

## Контроль качества

Targeted API/SQLite tests: постоянное хранение, 38 записей, курсор, owner isolation, ACL revocation, цитата не от того заседания, версия исходника. Migration risk: schema31→32, clean/repeat, `PRAGMA quick_check`, `PRAGMA foreign_key_check`, rollback при контролируемом сбое, backup/restore. Browser (desktop/mobile): raw/structured rendering, безопасный HTML, действия с документом, повторное открытие сохранённого ответа, отсутствие LLM, адаптивность.

Ответственность по зонам: `kafedra-flow-intake`, `kafedra-design`, `kafedra-data`, `kafedra-feature`, `kafedra-tests`. В текущем окружении отдельный runner агентов не предоставлен; коды и тесты интегрируются одним исполнителем, без фиктивного отчёта о параллельном выполнении.
