# Локальная авторизация и роли

Версия контура: `0.1.0-alpha.10`.

## Назначение

Авторизация связывает действия в системе с конкретным сотрудником и исключает доверие к произвольному `personId`, переданному браузером.

```text
локальный аккаунт → сотрудник → роль → разрешённая зона данных
```

## Роли

- `staff` — личные поручения, отчёты, план/факт и уведомления;
- `manager` — собственные данные, прямые подчинённые, контролируемые поручения, подтверждение и корректировка показателей;
- `admin` — аккаунты, роли, общие представления и полный административный доступ.

## Пароли

Пароль хранится как `scrypt`-хэш с индивидуальной случайной солью. Требуется не менее 12 символов, букв и цифр. После пяти неудачных попыток аккаунт блокируется на 15 минут.

## Сессии

Браузер получает случайный непрозрачный токен. В SQLite хранится только SHA-256 токена. Cookie имеет свойства:

- `HttpOnly`;
- `SameSite=Lax`;
- ограниченный срок действия;
- `Secure` при `KAFEDRA_AUTH_SECURE_COOKIES=true`.

Выход и сброс пароля отзывают серверные сессии.

## Первый администратор

Публичной регистрации нет. Первый администратор создаётся локально на сервере:

```bash
export KAFEDRA_ADMIN_USERNAME=admin
export KAFEDRA_ADMIN_PASSWORD='СложныйПароль2026'
export KAFEDRA_ADMIN_PERSON_NAME='Иванов Иван Иванович'
npm run auth:create-admin
```

Предпочтительно передавать пароль через защищённый файл:

```bash
npm run auth:create-admin -- --username admin --person-name 'Иванов Иван Иванович' --password-file /root/kafedra-admin-password
```

## Конфигурация

```text
KAFEDRA_AUTH_ENABLED=true
KAFEDRA_AUTH_COOKIE_NAME=kafedra_session
KAFEDRA_AUTH_SESSION_HOURS=12
KAFEDRA_AUTH_SECURE_COOKIES=false
KAFEDRA_AUTH_TRUST_PROXY=false
```

При работе через HTTPS необходимо включить `KAFEDRA_AUTH_SECURE_COOKIES=true`. Заголовок `X-Forwarded-For` учитывается только при явном `KAFEDRA_AUTH_TRUST_PROXY=true`.

## API

```text
GET  /api/auth/me
POST /api/auth/login
POST /api/auth/logout
POST /api/auth/change-password

GET   /api/admin/accounts
POST  /api/admin/accounts
PATCH /api/admin/accounts/:id
POST  /api/admin/accounts/:id/reset-password
```

## Ограничения доступа

- рабочее пространство берётся из сессии и не может быть подменено клиентским заголовком;
- сотрудник не может открыть уведомления другого сотрудника;
- руководитель видит только себя и прямых подчинённых;
- исправлять показатели могут руководитель в своей зоне контроля и администратор;
- владельцем личного сохранённого представления становится вошедший сотрудник;
- общие представления создают только руководитель и администратор;
- значимые действия записываются в `auth_audit_events`.

## Режим без авторизации

`KAFEDRA_AUTH_ENABLED=false` предназначен для разработки, миграционных проверок и существующих автономных тестов. В промышленной эксплуатации авторизация включена по умолчанию.
