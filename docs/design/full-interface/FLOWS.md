# Реестр пользовательских сценариев и вариантов окон

Основа: commit `688ffea1c6355980541da5ceb2b2e01f30116d76`, версия 0.4.7. Все строки ниже — задания на проверку и минимальное исправление, не отметки о выполненной приёмке. Перечень дополняется индивидуальными записями кнопок, полей, форм, окон и обработчиков source-index.

Для **каждой** строки обязательны применимые состояния из ACCEPTANCE: нормальный путь, отмена, ошибка/повтор, пустые/длинные данные, запрет доступа, повторное открытие и устойчивый результат после перезагрузки. Для асинхронного пути добавляются частичный успех, уход со страницы, устаревший ответ и повторный запрос. Это разные тестовые случаи, а не один «счастливый путь».

Инициатор учитывается отдельно: меню, основная кнопка, строка списка, календарь, поиск, уведомление, центр действий и программное продолжение могут вести к одной форме с разным контекстом. В каждой зоне сопоставить все строки её кнопочной ведомости и все исходные контексты с приведёнными путями. Неопределённая связь обработчика остаётся индивидуальным заданием H01, а не выпадает из охвата.

| X09 | Оформлятор недоступен → локальный сотрудник → назначение → задача | Автономность локальной работы и корректные связи |
| X10 | Долгая обработка → другой раздел/новый запрос/второй таб → возврат | Отмена устаревшего UI-ответа, устойчивое состояние сервера, отсутствие двойной записи |
| X11 | Открытая форма → истечение сессии/смена роли → ошибка → новый вход | Неутечка данных, безопасное восстановление, never-learn для прав/секретов |
| X12 | Любой основной путь без ЛЛМ/Интернета/анимации → тот же рабочий результат | Локальная функциональность, источник и понятная обратная связь |

## Небраузерные границы всего проекта

N01: установка автономного комплекта → проверка возможностей → первый PIN/рабочий экран. N02: обновление → сохранённые данные/настройки → прежние ссылки и сценарии. N03: сбой OCR/Office/worker → предметная диагностика → восстановление/повтор. N04: восстановление резервной копии/откат → прежний рабочий контекст. N05: настройка необязательного локального llama.cpp → доступен/нет/ошибка → обычный поиск. N06: сформированный документ/файл → открытие в целевом офисном окружении → полный читаемый результат.

Здесь не утверждается наличие отдельных GUI-экранов установки, резервного копирования или настройки ЛЛМ. Если управление находится в CLI/.env, это прямо фиксируется; дизайнер отвечает за понятность пути и сообщения, а профильный владелец — за техническую безопасность. Изменение установщика/auth/storage требует существующих риск-проверок, а не выполняется как косметическая правка.
