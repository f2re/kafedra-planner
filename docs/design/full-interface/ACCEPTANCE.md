# Поэлементные задания и критерии приёмки

Эти контракты применяются к **каждой** соответствующей записи source-index, кнопочной ведомости и развёрнутого inventory. Идентичная кнопка на мобильном экране — отдельное место использования. Контракт общий; состояние, источник, обработчик и доказательство — индивидуальные.

## Формат карточки работы

`ID → исходный commit → файл:строка:столбец → зона/исполнитель → экран/вариант окна → сценарий и инициатор → наблюдаемое текущее поведение → решение → изменение → критерии/состояния → доказательство → статус`.

До проверки: `запланировано` или `требуется уточнение`. После анализа: `сохранить`, `исправить`, `объединить`, `удалить после доказательства недостижимости`. После реализации: `готово к независимой проверке`. После проверки: `пройдено`, `нужна правка`, `заблокировано`; `неприменимо` разрешается только с объяснением. Наличие ID или строки не означает «пройдено».

## C01 — каждая кнопка и команда формы

Задание: установить единственное ожидаемое действие и связанный объект; проверить подпись, место в иерархии и обработчик. Сохранить корректную кнопку, исправить неоднозначную, объединить дубли только при совпадении предметного смысла.

Приёмка: видимое/доступное имя понятно; важное действие не обозначено одним неизвестным символом; Enter/Space работают по семантике; фокус виден; активная область пригодна для выбранного устройства; результат относится к текущему объекту; повторный клик не создаёт дубль; во время запроса имеется локальная обратная связь; недоступность объяснима; ошибка оставляет возможность исправить/повторить; успех подтверждён сервером. Отсутствие лишнего подтверждения проверяется отдельно от безопасности операции.

Для стрелок периода/порядка указать направление и объект в доступном имени. Для «Сохранить» дополнительно F01; для крестика/«Отмена»/«Закрыть» — W01; для перехода к другому объекту — C03; для удаления/архива — C02. Программно создаваемая кнопка без постоянной подписи проверяется на всех вариантах подписи.

## C02 — удаление, архивирование, восстановление и опасное изменение

Задание: разделить обратимый архив, удаление отдельного вопроса/назначения, изменение доступа, завершение сессий и необратимое действие. Не применять ко всем одну безымянную кнопку «ОК».

Приёмка: назван конкретный объект и последствие; отмена не изменяет данные; повтор безопасен; ошибка не скрывает объект; восстановление возвращает прежние связи и историю в рамках существующего контракта. Архив документа не удаляет заседание/план/доказательства. Удаление вопроса сохраняет корректную нумерацию и не ломает перенесённые связи. Права проверяются сервером, не только видимостью кнопки. Эти действия и их подтверждения не обучаются персональным подстановкам.

## C03 — ссылка и переход к источнику

Задание: проверить точное назначение каждой ссылки и перехода, включая оригинал, скачивание, источник значения, поиск, календарь и отчётную проекцию.

Приёмка: открывается нужный объект/версия/страница/строка, а не общий список; недоступный или удалённый объект объяснён; разрешения соблюдены; возврат восстанавливает запрос, фильтры, выбранную запись, прокрутку и фокус. Скачивание содержит действительный файл, понятное имя и корректный тип. Новое окно браузера не возникает неожиданно; вторичная ссылка не перехватывает основное нажатие по карточке.

## C04 — раскрытие, вкладка и вторичные параметры

Задание: проверить каждый summary/details, вкладку и переключатель режима; отделить раскрытие представления от изменения предметного значения.

Приёмка: состояние выбора/раскрытия доступно без цвета; клавиатура работает; активная вкладка и содержимое согласованы; закрытие дополнительных полей не удаляет уже введённое; ошибка в скрытом поле обнаружима; переключение не сбрасывает текущую задачу без причины. Редкий параметр можно найти, но он не конкурирует с основным действием.

## C05 — каждое поле ввода

Задание: определить источник и необходимость значения, тип, диапазон, формат и последствия. Удалить повторный запрос однозначно известного значения; не прятать необходимую ручную правку.

Приёмка: видимая подпись вместо одного placeholder; правильные дата/число/текст/пароль; русское пояснение формата и ошибки; длинный текст и вставка не ломают окно; неверное/неполное значение не превращается в выдуманное; после ошибки ввод сохранён; после успешной записи и перезагрузки значение корректно. Для даты из документа хранится исходная неоднозначность, а не произвольно выбранный день.

Hidden-поле не обязано иметь пользовательскую подпись и не должно попадать в Tab-порядок; вместо этого проверяются происхождение, актуальность и безопасная передача значения. Пароли/PIN/коды не входят в личные подстановки, URL или сохраняемые черновики. Файловое поле дополнительно C06; radio/checkbox/select дополнительно C08.

## C06 — каждый вход загрузки файла

Задание: проверить видимую кнопку/label, скрытый input, поддерживаемые форматы, одиночный/пакетный режим и тот же путь из центра действий.

Приёмка: видимый инициатор доступен клавиатурой; отмена выбора не создаёт запись; одинаковый файл не создаёт нежелательный дубль; повтор того же выбора работает; неправильный формат/размер объяснён; имена на русском передаются корректно; состояние отдельно для каждого файла; успешные соседние файлы не откатываются из-за одного сбоя. Показаны сохранение, обработка, готовность, необходимость проверки и ошибка без ложного общего успеха.

Повторная обработка не перезаписывает оригинал или ручное значение. Уход со страницы не выдаётся за отмену уже сохранённого фонового задания. Удаление неотправленного файла и архив сохранённого источника — разные действия. После возврата состояние берётся из устойчивых данных. Отсутствие OCR/Office/ЛЛМ сообщается предметно и не маскируется бесконечным ожиданием.

## C07 — все 15 команд центра действий

Задание: для каждой записи action-registry проследить поиск/ранжирование → доступность → вызов существующей формы → сохранение результата.

Приёмка: команда ведёт в правильный раздел и форму; дата/план/тип документа/другой контекст не теряется; запрет или поздняя загрузка модуля объясняются; отмена возвращает в исходное место; частотные рекомендации не переставляют основную навигацию; пустой поиск по командам исправим. Не создавать вторую реализацию команды внутри центра действий. Все команды перечислены в FLOWS, независимо от общего шаблона actionButton.

## C08 — каждое option, checkbox, radio и выбор из справочника

Задание: проверить все объявленные варианты и динамический список: пустой, один, несколько, длинные/одинаковые названия, неактивное и ранее сохранённое значение.

Приёмка: выбранное значение относится к правильному объекту и периоду; нейтральный вариант не подменяется первым; сохранённый/явный/domain-derived выбор имеет правильный приоритет; программная подстановка не обучает систему; неизвестное имя не угадывается; сброс/снятие выбора действительно обратимы. Массовый выбор ограничен указанной областью: видимые, отфильтрованные или все — это должно быть ясно. Изменение фильтра не должно незаметно применить массовое действие к другой группе.

314 source-option записей не доказывают проверку всех данных справочника. Фабрика вариантов требует перечисления классов данных и проверки всех значений конечных встроенных массивов. Неограниченные пользовательские данные проверяются классами эквивалентности, а не обещанием перебрать бесконечное множество строк.

## F01 — каждая форма и каждый её режим

Задание: перечислить создание/редактирование/просмотр/черновик/импорт и условные разделы, реально предусмотренные кодом. Для одной формы в общем окне это отдельные варианты.

Приёмка: можно начать, заполнить минимально необходимое, раскрыть редкое, исправить ошибку, сохранить, отменить, вернуться и открыть сохранённый результат. Проверить Enter без неожиданной отправки, двойной submit, отмену во время операции, устаревшие данные, отказ доступа и серверную ошибку. После повторного открытия нет значений от другого объекта. Граница между предпросмотром и записью очевидна. Успех на экране соответствует сохранённому состоянию после перезагрузки.

## W01 — каждое окно, инспектор в модальном режиме и системный диалог

Задание: указать контейнер, все фабрики/вызывающие функции, формы и инициаторы. Общий `meeting-modal`, `manual-plan-modal`, `lifecycle-modal` или фабрика `protocolDialog` не освобождают от проверки каждого варианта.

Приёмка: понятное имя окна; правильный первоначальный фокус; Tab/Shift+Tab не теряют пользователя; фокус виден; подложка и прокрутка соответствуют модальности; Escape, крестик, «Отмена», «Закрыть» и нажатие снаружи имеют согласованные последствия; несохранённый ввод не пропадает без предусмотренного решения; успех/ошибка не оставляют заблокированную подложку; возврат к живому инициатору либо безопасному соседнему элементу; повторное/вложенное открытие не создаёт дубликат и двойной обработчик.

На мобильном проверить виртуальную клавиатуру, прокрутку длинной формы и доступность основного действия. Немодальный инспектор не должен искусственно запирать фокус. Экран обязательного входа не обязан закрываться Escape: неприменимость объясняется границей авторизации. Системные prompt/confirm/alert учитываются отдельно, включая отмену каждого шага, а не считаются «вне интерфейса».

## S01 — каждый экран и представление

Задание: определить основную работу, входы, контекст, главное действие, вторичные панели и выходы. Учитывать серверные и поздние подключения.

Приёмка: нужный раздел достижим всеми предусмотренными способами; заголовок/период/фильтры соответствуют данным; пустое состояние объясняет следующий шаг; загрузка не стирает контекст; ошибка имеет восстановление; роль не раскрывает лишние данные; длинные строки, большая таблица, узкий экран и масштаб не прячут обязательное действие. Возврат не создаёт второй редактор источника истины. Сохранённые предпочтения не меняют геометрию произвольно.

## S02 — панель, меню, уведомление, статус и предпросмотр

Задание: проверить показ/скрытие, привязку к текущему объекту, объявление изменения и взаимодействие с окружающим экраном.

Приёмка: сообщение предметно, не дублируется от нескольких обработчиков, не исчезает раньше возможности прочитать, не перекрывает критическое управление и не существует только в цвете/движении. Окончание анимации не является условием действия. Предпросмотр ясно отличается от сохранённого результата; недоступность оригинала не заменяется выдуманным содержимым. Уведомление открывает нужный объект; прочтение/скрытие сохраняются по действующему контракту.

## H01 — каждый обработчик, вызов и неразрешённый кандидат

Задание: связать источник элемента → регистрацию/делегирование → проверку контекста/прав → вызов → результат/ошибку → обновлённый экран. Для createElement и нестандартного узла выяснить, является ли он интерактивным, окном, состоянием или технической конструкцией.

Приёмка: один пользовательский жест не вызывает две мутации; обработчик не действует на чужую вложенную кнопку/старый объект; поздняя загрузка и повторный enhancer не создают дубль; серверный отказ показан на нужном уровне; отменённый/устаревший ответ не заменяет новые данные; таймер/observer не стирает ввод и фокус. Технический узел можно исключить из интерактивных проверок только с записанным основанием. Отсутствие прямого import не доказывает недостижимость при серверной сборке или динамическом входе.

Вызовы генерации/открытия общего окна требуют отдельных записей его вариантов. Автоматически выбранный селектор — кандидат для проверки, не готовое разрешение нажимать его на рабочей базе. Ошибка парсера или непонятная динамика не превращаются в молчаливый пропуск.

## P01 — каждый CSS-файл и общий компонент

Задание: установить используемые токены, компоненты, состояния и ширины; найти реальных потребителей перед изменением правила.

Приёмка: нет второго набора случайных цветов/радиусов; нет локального исправления, сломавшего соседние формы; читаемость, контраст, активная область, таблицы, переполнение и видимый фокус сохранены. Не добавляются внешние шрифты/CDN, тяжёлая библиотека или непрерывные декоративные эффекты. Удаление правила допустимо после проверки потребителей. Цвет и анимация не являются единственным носителем состояния.

## Матрица состояний и данных

Для каждой записи определить применимость: обычное, hover, focus, active, selected, disabled, loading, empty, error, partial-success, success. Дополнительно для запросов: timeout, отсутствие сервиса, потеря связи, повтор, двойной клик, отмена/уход, устаревший ответ, второй таб, восстановление после перезагрузки. Для окон: открытие/закрытие всеми путями, грязная форма, повторное/вложенное открытие, удалённый инициатор.

Данные: ноль/один/много объектов, длинный русский текст, одинаковые имена, некорректная/неполная дата, отсутствующий источник, архивный объект, частично распознанный файл, несколько исполнителей, неподдерживаемый формат, истёкшая сессия и все фактически существующие роли/ограничения доступа.

Целевые ширины этого плана: 360, 768, 1280 и 1920 CSS px; дополнительно масштаб 200%, реальная клавиатура и сенсорный ввод. Это план испытаний, не утверждение о выполненных измерениях и не замена действующих Playwright-конфигураций. Для движения — обычный режим и `prefers-reduced-motion`; для статического элемента достаточно обоснованной неприменимости движения. Проверять поддерживаемые проектом темы; не добавлять новую тему как обязательную фичу аудита.

## Доказательство и запреты

Результат содержит commit, идентификаторы, применимые случаи, команду теста/трассу/снимок, ожидаемый и фактический результат. Снимок не доказывает сохранность, отмену, права или идемпотентность. Название существующего spec-файла — направление проверки, а не доказательство пройденного теста.

Нельзя тестировать реальные рассылки или опасные действия слепым обходом всех кнопок рабочей установки. Нельзя переносить прошлый PASS на изменённый элемент без оценки diff. Нельзя закрыть неизвестную ветвь `неприменимо` без причины. Нельзя уменьшить реестр, удалив строку о неудобной для проверки кнопке.
