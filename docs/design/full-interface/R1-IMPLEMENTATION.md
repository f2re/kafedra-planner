# R1 — общий рабочий интерфейс

Основа: `688ffea1c6355980541da5ceb2b2e01f30116d76`, задачи #360 / #362, PR #361.
Этот этап не закрывает полный план R0–R7. База, PIN/ACL, immutable source, установщик и workflows не меняются.

## Делегирование и интеграция

| Исполнитель | Отдельный предмет работы | Принято интегратором |
|---|---|---|
| Визуальный дизайнер | Общие кнопки, поля, подложки, навигация; календарь, фильтры планов и распоряжений на узкой ширине | Системные токены, устранение переполнения, читаемая кнопка «Добавить», сенсорные области, уменьшение blur |
| Проектировщик окон | Tab/Escape, фокус, файловые кнопки, вкладки | Один владелец Tab в центре действий, aria-selected у вкладок, однократный выбор файла |
| UX-дизайнер | Инспектор → редактор → возврат; календарь → план; повторное открытие шаблона | Ручная дата сохраняется, инспектор остаётся за редактором, предложение черновика видно вне скрытого шага |
| Независимый аудитор | Проверка интегрированного кода, а не проекта оформления | Выявлены и исправлены повторное создание удалённого черновика отложенным PUT и потеря точки фокуса после нативного диалога |
| Координатор | Согласование контрактов и исполнение приёмки | Проверка действующих компонентов и API; без второго редактора, без новой библиотеки и без анимации ради оформления |

Роли запускались как независимые LLM-задания с исходниками и локальным Designer. Первый широкий ответ UX-агента оказался обрезан; он не использовался как завершённый отчёт и заменён ограниченным повторным заданием. Аудит исходников не выдаётся за работу в браузере.

## Поведение

Окна получают доступное имя, удерживают клавиатурный фокус и закрываются по одному. Нативный диалог не пропускает команды открытия поиска/создания в нижележащий интерфейс. Нажатие «Продолжить редактирование» возвращает к прежнему полю. Явная «Отмена» не требует дополнительного подтверждения; случайное закрытие изменённой формы защищает ввод.

Редактирование календарной записи из инспектора сохраняет контекст просмотра. Исправленная дата пункта не заменяется исходным днём при обновлении DOM. Шаги мастера шаблона доступны как действующие кнопки; для перехода вперёд проверяются необходимые данные. Повторное восстановление черновика не удваивает поля. Очистка черновика выполняется после уже поставленных в очередь сохранений и только по подтверждённому результату; неудачная очистка не объявляется успешной.

## Воспроизводимая приёмка

`npx playwright test tests/browser/workspace-redesign.spec.mjs --project=desktop --project=mobile`

Утверждения находятся в `tests/browser/helpers/workspace-redesign-cases.mjs`. В ограниченной среде разработки они исполнялись тем же Playwright напрямую, без дополнительного процесса test worker. Это не замена утверждений упрощёнными проверками. Сервер/worker использовали отдельную одноразовую SQLite-базу; production-данные не затрагивались. OCR, Office, физическая клавиатура и ядро Astra этим прогоном не подтверждаются.

Проверяются все достижимые основные разделы на 360/768/1280/1920 и мобильной компоновке, переключение календарных режимов, общий стек окон, ошибка/повтор реального сохранения, однократное открытие выбора файла, вложенная структура, ручная дата, возврат к инспектору, восстановление/очистка черновика, тёмная тема и reduced-motion. Синтетические записи и вынужденная ошибка 503 существуют только в тесте.

## Поэлементный охват и оставшаяся работа

Индекс содержит индивидуальные координаты каждого элемента и вызова, владельца D1–D7 и соответствующие критерии ACCEPTANCE. Актуальные количества и SHA-256 находятся в `source-index.json`; воспроизведение — `tools/ui-audit/inventory.mjs`, проверка — `tools/ui-audit/check.mjs`.

Наличие записи не означает, что нажата каждая из 458 исходных кнопок или проверены все варианты 64 форм. R1 подтверждает перечисленные общие компоненты и сценарии; неохваченные варианты сохраняют статус «запланировано». Полная предметная приёмка D2–D7, парольные prompt, все динамические option и проверка реальной Astra-установки остаются в #360. Недостижимость двух старых модулей — кандидат исходного графа, не разрешение удалить код.

## Публикация

Используется подтверждённый GitHub write connector: tree/blob → commit с проверенным parent → update_ref с ожидаемым head → PR → обязательный CI → squash merge с ожидаемым SHA → проверка main и post-merge smoke. В этой сессии объявленный optional expected_sha у update_ref вернул argument_binding; после чтения head использован обычный fast-forward force=false. Локальный git commit и созданный Git Data объект без update_ref не называются публикацией в ветке.

Финальная локальная приёмка: 18/18 браузерных сценариев; точные имена, окружение и отпечатки — [R1-EVIDENCE.json](R1-EVIDENCE.json). Результаты CI и merge подтверждаются API GitHub и указываются в PR, не предсказываются в этом файле.
