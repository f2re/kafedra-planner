# Взаимодействие ИИ-агентов Кафедры и удалённого LLM-сервера

В системе «Кафедра-планер» и автономном комплексе «local-llm-offline» реализована микросервисная архитектура разделения бизнес-логики и вычислений модели.

## 1. Архитектура: как агенты появляются на удалённом сервере

Удалённый сервер нейросети (`llm.52kaf.vka:8081`, развёрнутый из проекта `local-llm-offline` на базе `llama-server`) является **вычислительным движком (stateless inference)**:
1. Модель (`Qwen2.5-7B` или `Qwen3-4B` в формате GGUF) не переобучается под кафедру и не содержит жёстко зашитых промптов.
2. Все агенты, их роли, задачи, валидаторы и связи с SQLite находятся на узле Кафедры в [packages/ai/src/assistant-tasks.mjs](file:///home/YaremenkoIA/kafedra-planner/packages/ai/src/assistant-tasks.mjs).
3. При каждом запросе оператора Кафедра динамически формирует:
   - Системный промпт выбранного агента (`role: "system"`);
   - Контекст документа или найденных фрагментов заседаний (`role: "user"`);
   - И отправляет стандартный вызов OpenAI-совместимого API: `POST /v1/chat/completions`.
4. Модель исполняет промпт на CPU/GPU и возвращает строго структурированный JSON, который Кафедра верифицирует на предмет отсутствия галлюцинаций.

Такая схема гарантирует, что **при добавлении новых агентов не требуется обновлять или перезапускать удалённый LLM-сервер**.

## 2. Экспорт промптов в проект `local-llm-offline`

Для администратора LLM-сервера в `kafedra-planner` предусмотрен скрипт экспорта:

```bash
node scripts/export-agent-prompts.mjs
```

Скрипт автоматически создаёт и обновляет в комплекте `local-llm-offline`:
- `integration/department-agents.json` — машиночитаемый манифест всех 9 агентов кафедры с системными промптами, лимитами токенов и примерами запросов;
- `integration/test-remote-agents.sh` — утилиту проверки любого агента через прямой HTTP-вызов `llama-server`;
- `integration/AGENTS_GUIDE.md` — справочник администратора сервера нейросети.

## 3. Принцип ненавязчивых рекомендаций (Советник по оформлению)

Режим подсказок к тексту (`compliance-check`) действует исключительно как доброжелательный помощник:
- **Никаких карательных ограничений:** убраны баллы (Score), тревожные предупреждения и блокировки сохранения документов.
- **Интерактивное одобрение:** если советник видит размытую формулировку поручения или пропуск срока, он предлагает готовый вариант замены (`suggestedFix`).
- **Применение в 1 клик:** оператор нажимает `[✓ Принять формулировку]` (или `[✓ Принять все предложения]`), и текст автоматически обновляется в поле ввода. Если оператор не нажал кнопку — текст остаётся в исходном виде.

## 4. Патч-бандл для переноса на удалённый LLM-сервер

Для доставки агентов, сетевой настройки и системной оптимизации удалённой машины с `local-llm-offline` собирается компактный автономный патч-бандл:

```bash
npm run bundle:patch:llm
```

Сборщик формирует архив `release/local-llm-patch-kafedra-agents-YYYYMMDD.tar.gz` (и копирует его в `local-llm-offline/integration/`), содержащий:
1. `apply-patch.sh` — скрипт автоматической установки манифеста, настройки `threads = nproc`, разрешения доступа по локальной сети (`host: 0.0.0.0`) и перезапуска `local-llm.service`.
2. `optimize-system.sh` — тюнинг ядра Linux для максимальной скорости CPU-инференса (CPU governor `performance`, Transparent Huge Pages, `sysctl`, `limits.d`).
3. `test-remote-agents.sh` — автономную утилиту экспресс-тестирования любого агента прямо на сервере нейросети.
4. `department-agents.json` — полный манифест всех 9 агентов кафедры с системными промптами.
5. `profiles/` — готовые конфигурационные профили производительности, включая `cpu-highperf-22threads-lan.json`.

### Применение на LLM-сервере:
```bash
# 1. Скопировать архив на сервер и распаковать:
tar -xzf local-llm-patch-kafedra-agents-YYYYMMDD.tar.gz
cd local-llm-patch-kafedra-agents/

# 2. Применить одной командой:
sudo ./apply-patch.sh

# 3. Проверить ответ модели:
test-kafedra-agents --all
```
