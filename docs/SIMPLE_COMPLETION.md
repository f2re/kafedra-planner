# Простое выполнение задач без согласований

Кафедра Planner автоматизирует бюрократическую работу, а не создаёт новый маршрут согласования.

## Основной поток

```text
план / распоряжение / заседание
            ↓
    задача и календарный срок
            ↓
      при необходимости правка
            ↓
        «Выполнено»
            ↓
 план · календарь · План / факт
```

Для завершения задачи не требуются:

- отчётный документ;
- подтверждение руководителя;
- возврат на доработку;
- отдельная карточка приёмки;
- обязательный комментарий.

Действие `Выполнено` сразу переводит поручение в `completed`. Существующий мост `plan_item → assignment` синхронизирует связанный пункт плана и календарную задачу. Повтор того же действия не создаёт новый предметный объект.

## Подтверждающие материалы

Сотрудник может приложить PDF, DOCX, скан, изображение или ранее загруженный документ. Материал:

- необязателен;
- хранится как обычная неизменяемая версия документа;
- связывается с существующим поручением;
- не меняет состояние задачи;
- может быть приложен до или после выполнения;
- при повторной привязке не создаёт второй `assignment_evidence`.

Автоматическое сопоставление документа с задачей работает как предложение необязательной связи. Принятие предложения не переводит задачу в `submitted` и не создаёт уведомление о необходимости проверки.

Внутреннее значение `evidence_kind=report` временно сохраняется для совместимости с существующим извлечением показателей `План / факт`. Оно не означает обязательный отчёт или согласование. Новая связь получает `review_status=not_required`.

## Старые данные

Исторические `assignment_updates`, evidence и отметки прежнего согласовательного потока не удаляются. В текущей итерации новые действия больше не создают состояния `submitted/rework/returned`. Их безопасная нормализация в существующих установках выполняется отдельным этапом обновления с проверкой backup/restore.

## Интерфейс

Карточка задачи содержит:

- одну основную кнопку `Выполнено`;
- необязательную заметку и готовность;
- обратимое действие `Вернуть в работу`;
- блок `Подтверждающие материалы` с явной пометкой, что файл не влияет на статус.

Формы `Подтвердить выполнение` и `Вернуть на доработку` не показываются. Старый API `/api/assignments/:id/review` возвращает `410 Gone` с пояснением, что подтверждение больше не требуется.

## Надёжность

- исходный файл и SHA-256 не изменяются;
- ошибка загрузки материала не блокирует завершение задачи;
- ошибка сопоставления материала не меняет поручение;
- приложение материала к уже выполненной задаче не открывает её повторно;
- права чтения документа и редактирования поручения проверяются как раньше;
- основной функционал не зависит от Интернета, LLM или Оформлятора.
