База аудита: `ca0ecd3e61c817e35b009f0738e2a59a1fa38525` (`main`, 0.4.6, SQLite 31). Основание — запрос на упрощение интерфейса и фоновую помощь ЛЛМ. [Манифест, сценарии и план](../BUREAUCRACY_ASSISTANT.md) определяют дальнейшую работу.

## Вывод

Переоформлять весь продукт с нуля не требуется. В репозитории уже есть предметные связи, неизменяемые документы, прямое завершение работы, поиск с возвратом в контекст, импорт протоколов и Apple-inspired правила. Следующий полезный шаг — готовить подходящие действия и материалы внутри этих сценариев, а не добавлять отдельный чат или очередной обязательный мастер.

Основной недостаток выбранного контура — разрыв между найденным материалом и подготовленным результатом. Человек по-прежнему должен оценить, что из выдачи подходит, перейти к источникам и решить, как использовать их в работе. Первая доработка помогает с отбором; сохранение доказуемой связи с отчётом остаётся следующим рубежом.

## Реализованная вертикаль

Новые файлы: `packages/ai/src/search-assistant.mjs`, `public/search-assistant.js`, `public/search-assistant.css`, модульные и API-тесты, целевой браузерный сценарий. Изменены существующие `apps/api/src/search-router.mjs` и `public/search-next.js`. Настройки, схема БД, установщик и исходные документы не меняются.

Сценарий: ввод → обычная выдача → 700 мс спокойного ввода → фоновая очередь → проверка ответа → счётчик найденных выдержек → раскрытие по желанию пользователя → существующее открытие источника и возврат. Никакого автоматического прикрепления, выпуска документа или изменения статуса.

Реестр состояний: выключено, нет материала, ожидает, выполняется, готово, занято, ответ отклонён, сервис недоступен. Повторный поиск отменяет устаревшую работу; запоздалая отмена не затрагивает новое поколение. Опрос не запускает новую генерацию. Перезапуск приложения теряет только временную подборку.

Сохраняется существующий адрес модели. Нет нового облачного провайдера, SQL от модели, чтения произвольных файлов, выполняемых команд или массовой отправки базы. Текст и идентификаторы результата проходят локальную проверку; в интерфейсе выдержки выводятся через `textContent`.

- `node --test tests/search-assistant.test.mjs`: 17 тестов прошли в среде подготовки, Node 22.16.0. Это не подмена заявленного проектом Node 24 и не полный проектный прогон.
- Проверка синтаксиса изменённых JS/MJS выполнена локально.
- Поисковый компонент проверен Chromium 144 с тестовым транспортом: 1360×900, 390×844 и режимом уменьшения движения. Проверены фоновая выдача, отсутствие перестановки/захвата фокуса, раскрытие, источник/возврат, отключение запросов, недоступность модели, отсутствие горизонтального переполнения и ошибок JavaScript. Это компонентная проверка, а не сквозной прогон установленного приложения.
- В репозиторий добавлен тест реального API с локальным HTTP-сервером, имитирующим только модель: отсутствие блокировки, обязательный заголовок, неизменная обычная выдача, игнорирование клиентских кандидатов, дедупликация и инвалидация при изменении источников.
- Добавлен Playwright-сценарий с реальными поиском/данными приложения и подменой только ответов помощника. Его проектный запуск и точный статус CI фиксируются в PR; наличие файла теста не означает успешный прогон.
- Реальный `llama-server`, качество на ведомственных документах, скорость на CPU Astra, физическая установка и полная регрессия всех разделов в этой среде не проверены.

## Следующая приёмка

До слияния проверить точный head проектным CI, реальный API-тест, существующие ACL-сценарии и целевой браузерный тест. До включения у пользователей проверить на обезличенных реальных запросах полезность отбора и отсутствие ложных подтверждений. Раздельно учитывать корректность источника, уместность подсказки и факт выполнения: это три разные проверки.

Для следующего этапа взять один настоящий отчёт и пройти путь «связанные факты → подходящие документы → заполненные строки → источники → выпуск». Не добавлять универсальный генератор форм раньше, чем станет понятно, какие исключения не покрываются существующими шаблонами.

## Внешний технический источник

Контракт HTTP и ограниченного JSON проверен по официальной документации [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), раздел `/v1/chat/completions`, 19.09.2026. Используется `response_format` с JSON Schema и один ограниченный повтор без него для несовместимого сервера; локальная проверка обязательна в обоих режимах. Дизайн основан на собственном действующем `docs/design.md`, а не на неподтверждённом пересказе изменяющихся рекомендаций Apple.
