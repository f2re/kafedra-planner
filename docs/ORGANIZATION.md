# Организационная структура и кадровая история

## Назначение

Организационная структура хранится как исторические данные, а не как набор текущих строк в карточке сотрудника. Это позволяет формировать отчёт за прошлый период по фактическому подразделению, должности и руководителю на дату документа.

```text
organizational_unit
 ├─ период действия
 ├─ родительское подразделение
 └─ person_appointment
      ├─ сотрудник
      ├─ должность
      ├─ руководитель
      ├─ основное/дополнительное
      └─ период действия
```

## Подразделения

Поддерживаются организация, факультет, кафедра/подразделение, лаборатория, секция и произвольный иной тип. Для каждого подразделения сохраняются:

- полное и краткое название;
- необязательный код;
- родительское подразделение;
- дата начала и окончания действия;
- состояние;
- источник и аудит изменений.

Период дочернего подразделения обязан входить в период родительского. Изменение периода не допускается, если оно сделает существующее дочернее подразделение или назначение сотрудника недействительным. Циклическая структура запрещена.

## Должности

Должность — отдельный справочник рабочего пространства. Отключить должность нельзя, пока она используется в действующем назначении. Исторические назначения сохраняют ссылку на должность даже после её отключения.

## Назначения сотрудников

Назначение содержит подразделение, должность, руководителя, вид и период действия. Основные назначения одного сотрудника не могут пересекаться. Дополнительные назначения могут действовать параллельно.

При создании нового основного назначения система безопасно закрывает предыдущее накануне, если оператор не отключил этот режим. Исправление существующего периода требует причины и фиксируется в аудите. Циклическая цепочка руководителей запрещена.

Поля `people.position` и `people.manager_id` остаются совместимой проекцией текущего основного назначения; историческим источником истины является `person_appointments`.

## Научные аффилиации

Для автора научного материала фиксируется аффилиация на дату публикации. При наличии назначения система создаёт снимок подразделения и должности. Перевод сотрудника в будущем не меняет отчётность за прошлый год.

Оператор может исправить аффилиацию по опубликованному документу. Такая коррекция:

- требует причины;
- маркируется как ручная;
- не уничтожает автоматически полученную историю;
- фиксируется в аудите.

## Обновление существующей установки

Миграция схемы 20:

- создаёт корневое подразделение для каждого рабочего пространства;
- переносит уникальные текущие должности из `people.position`;
- создаёт основные назначения из текущих полей сотрудника;
- формирует исторические научные аффилиации для уже зарегистрированных авторов;
- не изменяет и не удаляет исходные документы;
- не ослабляет существующие ACL.

Перед обновлением выполняются резервное копирование и проверка восстановления. После миграции обязательны `PRAGMA foreign_key_check`, `PRAGMA quick_check` и сравнение логических digest устойчивых таблиц.

## API

```text
GET    /api/organization?asOf=YYYY-MM-DD
POST   /api/organization/units
PATCH  /api/organization/units/:id
POST   /api/organization/positions
PATCH  /api/organization/positions/:id
GET    /api/people/:personId/appointments
GET    /api/people/:personId/organization?asOf=YYYY-MM-DD
POST   /api/people/:personId/appointments
PATCH  /api/appointments/:id
PUT    /api/science/:itemId/authors/:authorRaw/affiliation
```

Чтение собственной истории доступно сотруднику в пределах общей политики доступа. Изменение структуры, должностей, назначений и аффилиаций выполняет администратор.

## Проверки

Unit/integration покрывают:

- разрешение назначения на историческую дату;
- запрет пересечения основных назначений;
- дополнительное назначение;
- закрытие предыдущего назначения;
- циклы подразделений и руководителей;
- обязательную причину исправления;
- научную аффилиацию на дату публикации;
- миграцию существующих текущих полей;
- внешние ключи и SQLite quick check.

Playwright проверяет desktop и mobile: создание подразделения, должности, назначения, просмотр истории, выбор даты и сохранение пользовательского ввода при ошибке пересечения.
