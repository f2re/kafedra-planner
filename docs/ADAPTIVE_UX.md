# Обучаемые пользовательские значения по умолчанию

## Задача

Интерфейс сокращает повторный ручной ввод, но остаётся визуально стабильным. Система обучается только на **явных выборах человека** и использует накопленную частоту как безопасную подсказку для следующего аналогичного действия.

Это не рекомендательная система и не источник предметных фактов. Ошибка этого слоя не должна мешать сохранить задачу, заседание, документ или шаблон.

## Что никогда не меняется от частоты

- расположение кнопок;
- порядок вкладок и разделов;
- расположение основных полей формы;
- наличие обязательных проверок;
- права доступа;
- уже сохранённое значение существующего объекта.

Поэтому интерфейс не «плывёт» между открытиями страницы.

## Что может обучаться

### Раскрывающиеся списки

Варианты внутри списка могут ранжироваться по частоте явного выбора конкретным аккаунтом. Самый частый допустимый вариант становится значением по умолчанию нового действия.

Пример: если Иванов явно выбирался председателем 8 раз, Петров 3 раза, Сидоров 1 раз, при отсутствии сохранённого председателя Иванов показывается первым рабочим вариантом и выбирается по умолчанию. Пользователь может сразу выбрать другого сотрудника.

### Checkbox / radio

Для нового действия используется наиболее частое явно выбранное состояние. Простое отображение автоматически установленной галочки не считается выбором.

### Группы кнопок

Можно запоминать наиболее частый стартовый режим, но порядок кнопок остаётся постоянным. Например `Месяц / Неделя / Задачи` всегда расположены одинаково, даже если пользователь чаще работает в режиме `Неделя`.

Ранее существовавшее клиентское `last-mode` не является отдельным источником истины: обученный самый частый режим имеет приоритет при новом открытии. Явный выбор пользователя в текущем сеансе немедленно становится текущим режимом и учитывается в дальнейшей статистике.

### Повторно используемый текст

Разрешается только для специально помеченных несекретных словарных значений. В первой реализации это внутренний вид шаблона документа.

Никогда автоматически не сохраняются как обучающие значения:

- пароли и токены;
- поисковые запросы;
- комментарии;
- названия документов, событий и задач;
- текст вопросов, решений и отчётов;
- другой произвольный деловой текст.

## Когда увеличивается частота

Частота увеличивается только если одновременно выполнены условия:

1. пользователь действительно изменил контрол;
2. основное действие успешно завершилось;
3. значение входит в разрешённый контекст;
4. это не повторная доставка того же `interactionId` для того же контекста.

Если форма открылась с автоматически предложенным значением и пользователь просто нажал `Сохранить`, частота этого значения не изменяется.

## Приоритет значения

```text
сохранённое значение существующего объекта
        ↓
явный выбор пользователя в текущем действии
        ↓
персональный самый частый выбор
        ↓
статический безопасный fallback продукта
```

## Хранение

`ui_choice_preferences` хранит по одной компактной строке на явный выбор:

- workspace;
- account;
- разрешённый context key;
- выбранное значение;
- `interaction_id` пользовательского действия;
- время выбора.

Первичный ключ `workspace + account + context + interaction_id` делает повторную доставку одного действия идемпотентной. Частота вычисляется обычным `COUNT(*)` по значениям, а время последнего выбора — `MAX(selected_at)`. Отдельный журнал и агрегированный счётчик не нужны.

Предпочтения не записываются в предметный аудит и не являются доказательствами. Они входят в обычный SQLite backup/restore.

## Разрешённые контексты первой версии

| Контекст | Назначение |
|---|---|
| `calendar.mode` | стартовый режим `Месяц / Неделя / Задачи`, без перестановки кнопок |
| `calendar.new.kind` | событие или задача |
| `calendar.new.category` | категория новой календарной записи |
| `calendar.new.importance` | важность новой записи |
| `calendar.new.reminder` | срок напоминания |
| `template.field.required` | состояние галочки «Поле обязательно» |
| `template.document.type` | повторно используемый внутренний вид документа |
| `meeting.chairperson` | председатель в настройках заседаний |
| `meeting.secretary` | секретарь в настройках заседаний |

Новый context key нельзя добавлять только из соображений удобства реализации: сначала нужно доказать, что значение безопасно повторно использовать и что его автоматическое предложение не создаёт предметную ошибку.
