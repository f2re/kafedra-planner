# Работа с исправлениями и экспортом «План / факт»

## Когда нужна ручная корректировка

Исправление применяется, когда машинный показатель извлечён неверно либо подтверждённый источник содержит уточнённое значение, которое нельзя безопасно применить автоматически.

Перед сохранением оператор видит машинное и эффективное значения. Причина обязательна. Исходный документ, extraction evidence и прежние ревизии не изменяются.

## Порядок работы

1. Откройте `План / факт`.
2. Выберите сотрудника/период/направление или сохранённое представление.
3. Откройте обязательство.
4. Исправьте план или факт.
5. Укажите новое значение и причину.
6. Проверьте пересчитанные показатели и источник.

Отмена активной корректировки возвращает предыдущую действующую ревизию, а при её отсутствии — машинный результат.

## Сохранённые представления

Набор безопасных фильтров можно сохранить как личное либо разрешённое общее представление. Сохранённое представление не меняет предметные данные и не расширяет ACL.

## Экспорт

CSV выгружается в UTF-8 с `;`. JSON сохраняет структурированный состав текущей выборки, эффективные значения и доступную историю источников. Экспорт использует текущие серверные фильтры и права доступа.

## Проверка из source checkout

Эти команды относятся только к рабочему checkout разработчика:

```bash
npm run migrate
npm run check
npm test
npm run smoke
npm run test:browser:plan-fact
```

## Проверка установленной Astra/Debian системы

На production target npm не нужен. Используйте embedded runtime и штатную диагностику:

```bash
sudo /opt/kafedra-planner/current/scripts/offline/doctor.sh
```

Для release/restore acceptance снимайте evidence штатным CLI:

```bash
sudo /opt/kafedra-planner/current/runtime/node/bin/node \
  /opt/kafedra-planner/current/scripts/target-acceptance.mjs capture \
  --config /etc/kafedra-planner/kafedra-planner.env \
  --require-full \
  --output /root/kafedra-acceptance.json
```

Подробно: [`TARGET_ACCEPTANCE.md`](TARGET_ACCEPTANCE.md).
