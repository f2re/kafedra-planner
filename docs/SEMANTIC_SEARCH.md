# Поиск по теме и похожие материалы

Контракт поиска версии `0.4.7`. Основание: issues #358, #359 и PR #357. Направление развития описано в [манифесте помощника](BUREAUCRACY_ASSISTANT.md), промпты — в [SEARCH_LLM_PROMPTS.md](SEARCH_LLM_PROMPTS.md).

## Пользовательский сценарий

Введите тему обычными словами, например «отчёт где была статья про циклоны». Сначала отображаются результаты локального поиска. Он выделяет содержательные слова, пробует ограниченный набор русских окончаний и, если совпадений нет, близкое написание одного слова из действующего индекса. Это не полный морфологический анализ и не универсальная коррекция ошибок.

Когда ЛЛМ включена, через 700 мс после готовой выдачи начинается дополнительный поиск. Модель предлагает до трёх формулировок; сервер выполняет их по существующему индексу с теми же условиями и правами. Затем модель выбирает до пяти выдержек из полученных фрагментов. Пустая первоначальная выдача не запрещает этот этап.

Результат не заменяет исходную выдачу. Дополнительные источники находятся в свёрнутом блоке «Показать материалы». В нём доступны тип, название, выдержка, известные реквизиты и страница, когда она есть в локаторе. Нажатие открывает обычную рабочую карточку; «К поиску» восстанавливает исходный запрос и условия.

Похожие запросы показываются только при наличии доступных результатов. «Похожие материалы» у карточки строит запрос из её заголовка. Выбор новой формулировки меняет только текст: период, сотрудник и другие явные фильтры сохраняются. Подсказки отключаются переключателем в текущей вкладке. Уход из раздела, скрытие вкладки и новый запрос прекращают опрос устаревшей задачи.

## Индекс

Используются текущие `search_fragments` и `search_fts`. Временный `fts5vocab` читает словарь этого индекса для поиска близких написаний; постоянная схема SQLite 31 не меняется. Документы не копируются в новое хранилище, обязательных эмбеддингов нет.

Смысловое расширение здесь означает предложенные моделью поисковые термины с последующим поиском реальных записей. Это **не векторный поиск** и не гарантия обнаружить любое смысловое соответствие. Если модель не подобрала подходящую формулировку, нужный документ может остаться ненайденным.

Числа и даты не исправляются по сходству. Словарь ограничен выборкой до 600 терминов по первой букве и длине; пробуются не более трёх вариантов, меняется не более одного слова в формулировке. Скрытые термины не становятся подсказками только из-за присутствия в словаре: вариант показывается лишь после поиска доступных результатов.

## Границы доступа и источников

Все поисковые формулировки проходят те же выбранные фильтры и предметные проверки доступа. Перед передачей фрагментов повторно разрешается текущая сессия, затем проверяется доступ к каждому кандидату. Ответ модели не содержит произвольных адресов или запросов к базе: разрешены только ID переданных источников и точная выдержка из переданного текста.

При опросе готовой подборки источники и права проверяются заново. Изменившиеся кандидаты инвалидируют кэш. Архивные источники исключаются по умолчанию; старые версии документа не выдаются вместо текущей. Оригиналы, извлечённые факты и пользовательские исправления не изменяются.

Цитата проверяется по фрагменту индекса. Она подтверждает наличие текста в доступном поисковом материале, но сама по себе не доказывает исполнение работы, публикацию или принятие решения. План, отчёт и обсуждение в протоколе остаются разными предметными объектами.

## Ограничения фоновой обработки

| Параметр | Значение |
|---|---|
| Задачи модели | Расширение запроса, затем выбор выдержек |
| Поисковые формулировки | До 3, до 6 слов и 96 символов |
| Кандидаты для выбора | До 12, фрагмент до 600 символов, заголовок до 160 |
| Выдержки | До 5, от 16 до 240 символов |
| Выходные токены | До 256 для расширения, до 768 для выбора |
| Контекст | Дополнительно ограничен размером настроенного контекста; лишние кандидаты не передаются |
| Очередь | Одна активная задача помощника, до 8 ожидающих |
| Тайм-аут | Общий для обоих вызовов, не более 30 секунд и настроенного тайм-аута |
| Пауза после отказа | 60 секунд |
| Кэш | До 64 записей в памяти, до 120 секунд |
| Опрос | До 12 запросов с увеличением интервала; без бесконечного опроса |

Одинаковые запросы объединяются. Отмена, поступившая до запоздалого запуска того же поколения, запрещает его выполнение. Сервер не начинает новую генерацию по обычному поисковому URL или простому опросу: запуск требует отдельного заголовка, контекста вкладки и поколения.

Невалидный JSON, неизвестный ID или неподтверждённая цитата отклоняются. Если поиск уже нашёл полезные материалы, отказ выбора выдержек сохраняет их как частичный результат без выдуманного текста. При полном отказе остаётся обычная выдача. Перезапуск приложения теряет только временные подсказки, не рабочие записи.

Очередь пока относится к поисковому помощнику, а не ко всем запросам приложения: распознавание распоряжений использует существующий отдельный контур. Общий диспетчер и приоритеты относятся к дальнейшему развитию #88.

## Настройка

Используются существующие `KAFEDRA_LLM_ENABLED`, `KAFEDRA_LLM_ENDPOINT`, `KAFEDRA_LLM_MODEL`, `KAFEDRA_LLM_TIMEOUT_MS`, `KAFEDRA_LLM_MAX_TOKENS` и `KAFEDRA_LLM_CONTEXT_SIZE`. По умолчанию модель выключена. Настроенный администратором локальный сервер должен поддерживать совместимый `/v1/chat/completions`; существующее развёртывание описано в [LLAMA_OFFLINE_DEPLOYMENT.md](LLAMA_OFFLINE_DEPLOYMENT.md).

Модель не выбирает внешний сервис и не получает инструментов записи. Адрес с учётными данными, query или fragment не используется; перенаправления запрещены. Доступность определяется реальным ограниченным вызовом и паузой после отказа, без отдельного постоянного опроса здоровья сервера.

## Проверка и ограничения выпуска

Модульные тесты проверяют настоящий SQLite FTS5 и контролируемые ответы модели. API-тест запускает приложение с авторизацией, фильтрами, скрытыми и архивными документами и отзывом доступа. Браузерные тесты используют реальные данные приложения; подменяются только ответы необязательного помощника.

Конкретные результаты прогонов фиксируются в GitHub CI на точном коммите. Наличие тестов не означает, что реальная GGUF-модель уже оценена на ведомственных документах. Для её включения следует отдельно проверить уместность находок и время ответа на целевом сервере. Автоматическое заполнение сохраняемого официального отчёта, применение связей и отмена применения в эту версию не входят.
