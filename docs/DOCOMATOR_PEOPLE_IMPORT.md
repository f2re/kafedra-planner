# Импорт сотрудников из Оформлятора

Kafedra Planner может подключаться к Оформлятору в локальной сети и переносить его реестр сотрудников в справочник кафедры. Интеграция необязательна: документы, планы, задачи, календарь и ручной справочник полностью работают без Оформлятора и без сети.

## Где находится настройка

Откройте **Настройки → Структура кафедры → Импорт из Оформлятора**.

В форме есть только два поля:

- **Адрес Оформлятора** — полный URL, hostname или IP;
- **Код доступа** — необязательные четыре цифры только для текущего запроса.

Протокол, порт и версия API не вводятся отдельно.

## Какой адрес вставлять

Проще всего скопировать адрес из браузера:

```text
http://192.168.1.50:8080
https://docomator.local
http://docomator.local:8080/api/v1
http://[fd00::25]:8080/readyz
```

Поддерживаются:

- `http://` и `https://`;
- DNS-имя;
- IPv4;
- IPv6 в квадратных скобках, а для bare IPv6 — автоматическая нормализация;
- URL без явного порта с обычным портом протокола;
- hostname/IP без схемы с совместимым default `http://…:8080`;
- известные окончания `/api/v1`, `/healthz`, `/readyz` и `/api/v1/system/*`.

Известное окончание удаляется, и Planner сохраняет канонический origin сервиса. Например:

```text
http://docomator.local:8080/api/v1/system/info
→ http://docomator.local:8080
```

До сетевого запроса отклоняются:

- логин или пароль внутри URL;
- query string и fragment;
- `file:`, `ftp:` и другие схемы;
- посторонний path, который нельзя однозначно отнести к API Оформлятора;
- пустой или некорректный hostname/port.

Отдельное поле «Версия API» не нужно. Planner использует стабильные маршруты `/api/v1` и проверяет фактическую совместимость ответов.

## Почему могла появляться ошибка DNS

Запрос к Оформлятору выполняет сервер Kafedra Planner, а не браузер оператора. Поэтому имя `docomator.local` должно разрешаться именно на машине, где работает Planner.

Проверьте на сервере Planner:

```bash
getent hosts docomator.local
```

Если локального DNS или mDNS нет, вставьте IP-адрес Оформлятора, например `http://192.168.1.50:8080`. Не нужно вручную вырезать протокол или переносить порт в отдельное поле: версия `0.4.2` принимает весь URL целиком.

## Что делает «Подключить»

Проверка выполняется последовательно:

1. `/healthz` — отвечает ли именно Оформлятор;
2. `/readyz` — готовы ли база данных и runtime;
3. `/api/v1/spaces` — доступны ли прикладные данные;
4. после выбора пространства — группы и сотрудники;
5. `/api/v1/knowledge/property-definitions` — доступны ли свойства сотрудников.

Актуальный Docomator возвращает `/readyz` с HTTP 200 и `status: "ok"`. Planner `0.4.2` принимает это значение и legacy `status: "ready"`.

Redirects не выполняются. Если по адресу отвечает reverse proxy, он должен отдавать Docomator на указанном origin без перенаправления к другому host/path.

После нормализации интерфейс показывает фактический endpoint и, если он доступен, версию Оформлятора.

## Код доступа

Если Оформлятор закрыт четырёхзначным кодом:

1. вставьте адрес;
2. нажмите **Подключить**;
3. при состоянии **Доступен · нужен код** введите четыре цифры;
4. повторно нажмите **Подключить**.

Код:

- передаётся только в текущем check/import request;
- не записывается в SQLite;
- не записывается в конфигурацию;
- не возвращается GET API;
- не восстанавливается в поле после перезагрузки;
- не должен попадать в журнал.

## Выбор источника

После успешного подключения выберите:

- пространство Оформлятора;
- конкретную группу либо **Все сотрудники пространства**;
- при необходимости **Включить неактивных**.

Если активное пространство одно, оно выбирается автоматически и сразу загружается preview. Программная подстановка не считается пользовательским обучающим выбором.

До импорта показываются:

- количество найденных сотрудников;
- короткий список ФИО;
- доступные поля;
- время предыдущего импорта.

## Выбор полей

ФИО переносится всегда и используется для первичного сопоставления.

Для локальных колонок можно выбрать:

- поле Оформлятора для `E-mail`;
- поле Оформлятора для `Должность`.

Остальные свойства — телефон, подразделение, учёная степень и другие — выбираются чекбоксами. Они хранятся отдельно со стабильным remote property key, исходной подписью, типом и временем синхронизации. Основная таблица `people` не раздувается произвольными колонками.

Mapping сохраняется до отправки import request. Если выбранное remote property исчезло или изменилось, импорт не продолжает молча: интерфейс просит обновить список полей.

## Правила синхронизации

Импорт не очищает локальный справочник и не удаляет связанные объекты.

Для каждого сотрудника сохраняется связь с `remote employee id`. При первом импорте существующий локальный человек может быть сопоставлен по нормализованному ФИО. Дальнейшие синхронизации используют сохранённый remote id и обновляют ту же запись.

Сохраняются:

- локальные планы и пункты;
- задачи и исполнители;
- материалы и документы;
- назначения и оргструктура;
- заседания и отчёты;
- audit history.

Если связанный удалённый сотрудник стал неактивным и включён импорт неактивных записей, локальная запись переводится в `inactive`, но история и ссылки остаются.

## Partial success

Сетевые списки и профили загружаются до локальной транзакции. При обработке сотрудников ошибка одной записи не должна отменять остальные.

Итог показывает:

```text
total · created · updated · matched · skipped
```

Ошибочный профиль учитывается как `skipped` с безопасной причиной. Успешно созданные и обновлённые люди сохраняются. Повторный запуск снова обрабатывает тот же источник без создания дублей.

## Безопасная диагностика

| Код | Что означает | Что проверить |
| --- | --- | --- |
| `docomator_url_invalid` | вставлен некорректный или небезопасный URL | схему, hostname/IP, отсутствие credentials/query/fragment |
| `docomator_dns_failed` | имя не разрешается на сервере Planner | локальный DNS, `/etc/hosts` или прямой IP |
| `docomator_connection_refused` | host найден, но порт отклонил соединение | службу Оформлятора и port |
| `docomator_timeout` | сервер не ответил вовремя | сеть, firewall и загрузку сервиса |
| `docomator_tls_failed` | не установлено HTTPS-соединение | сертификат и имя узла |
| `docomator_wrong_service` | отвечает другой HTTP-сервис | адрес, port и reverse proxy |
| `docomator_not_ready` | процесс работает, но база/runtime не готовы | `/readyz` и journal Оформлятора |
| `docomator_access_denied` | код не принят | текущий код Оформлятора |
| `docomator_protocol_error` | ответ не соответствует ожидаемому API | версии приложений и proxy response |

Пользовательскому интерфейсу и сохранённому статусу не передаются код доступа, cookie, stack trace, сырой response body или внутренние пути.

## API Kafedra Planner

- `GET /api/integrations/docomator` — сохранённые параметры и mapping без кода;
- `PUT /api/integrations/docomator` — сохранить один URL, источник и поля;
- `POST /api/integrations/docomator/check` — проверить endpoint и получить spaces/groups/preview;
- `POST /api/integrations/docomator/fields/discover` — получить свойства сотрудников;
- `POST /api/integrations/docomator/import` — выполнить идемпотентный partial import;
- `GET /api/integrations/docomator/people/:personId/fields` — прочитать внешние свойства локального человека.

Изменяющие операции доступны администратору. При отключённой авторизации применяется обычный локальный режим Planner.

## После обновления Planner

Проверьте активную версию и перезапустите рабочее ядро:

```bash
cat /opt/kafedra-planner/current/VERSION
sudo systemctl restart kafedra-planner-api.service kafedra-planner-worker.service
sudo systemctl status --no-pager -l kafedra-planner-api.service kafedra-planner-worker.service
```

Для диагностики:

```bash
sudo journalctl -u kafedra-planner-api.service -u kafedra-planner-worker.service -n 100 --no-pager
```
