# Импорт сотрудников из Оформлятора

Kafedra Planner может подключаться к установленному в локальной сети Оформлятору и переносить его реестр сотрудников в справочник кафедры.

## Где находится настройка

Откройте **Настройки → Структура кафедры → Импорт из Оформлятора**.

Укажите:

- протокол `HTTP` или `HTTPS`;
- адрес сервера, например `192.168.1.50` или `docomator.local`;
- порт; стандартный порт Оформлятора — `8080`;
- при необходимости четырёхзначный код доступа Оформлятора.

Код доступа не записывается в SQLite, конфигурационные файлы или журнал Kafedra Planner. Он используется только для текущего запроса к Оформлятору.

## Что делает «Проверить соединение»

Проверка выполняется сервером Kafedra Planner, поэтому адрес Оформлятора должен быть доступен именно с машины, где запущен Kafedra Planner.

Последовательно проверяются:

1. `/healthz` — процесс Оформлятора отвечает;
2. `/readyz` — база данных и runtime готовы;
3. `/api/v1/spaces` — доступна прикладная информация;
4. после выбора пространства — группы и сотрудники;
5. `/api/v1/knowledge/property-definitions` — доступны определения полей сотрудников.

Интерфейс различает состояния «сервер недоступен», «сервер запущен, но не готов», «нужен код доступа» и «список сотрудников доступен». HTTP redirects не выполняются.

## Выбор сотрудников

После успешной проверки выберите пространство Оформлятора. Затем можно импортировать:

- всех сотрудников пространства;
- только участников выбранной группы;
- при необходимости включая неактивных сотрудников.

Перед импортом показываются количество найденных сотрудников и короткий предварительный список ФИО.

## Выбор полей

ФИО переносится всегда и используется для первичного сопоставления. После выбора пространства Kafedra Planner читает стабильные `property definitions`, применимые к сущности `person`, и показывает их в интерфейсе.

Для стандартных локальных колонок можно отдельно выбрать:

- какое поле Оформлятора записывать в `E-mail`;
- какое поле записывать в `Должность`.

Система предлагает наиболее вероятное соответствие по ключу, подписи и aliases, но оператор может выбрать другое поле или отключить перенос этой колонки.

Остальные свойства — телефон, подразделение, учёная степень и любые другие поля сотрудников — выбираются чекбоксами. Они сохраняются отдельно с исходным `remote employee id`, стабильным ключом свойства, подписью, типом и временем синхронизации. Это позволяет не раздувать основную таблицу `people` произвольными колонками.

Перед импортом выбранные ключи повторно сверяются с текущей схемой Оформлятора. Если администратор Оформлятора удалил или переименовал выбранное поле, Kafedra Planner не продолжает молча: он просит обновить список полей и подтвердить новую настройку.

Профили сотрудников загружаются с ограниченным параллелизмом. Сетевые запросы завершаются до транзакции изменения локальных значений, поэтому медленный Оформлятор не держит SQLite-транзакцию открытой.

## Правила синхронизации

Импорт не очищает справочник Kafedra Planner и не удаляет связанные задачи, планы или отчёты.

Для каждого сотрудника сохраняется связь с его `remote employee id` в Оформляторе. При первом импорте существующий сотрудник Kafedra Planner также может быть сопоставлен по нормализованному ФИО. Повторный импорт обновляет уже связанную запись вместо создания дубля.

Если в Оформляторе связанный сотрудник стал неактивным и включён импорт неактивных записей, локальная запись переводится в состояние `inactive`. История назначений и ссылки на сотрудника сохраняются.

Значения дополнительных выбранных свойств обновляются по паре `person + remote property key`. Пропавшее значение выбранного дополнительного поля удаляется только из таблицы внешних свойств; локальные задачи и история человека не затрагиваются.

## API Kafedra Planner

- `GET /api/integrations/docomator` — сохранённые параметры подключения и field mapping без кода доступа;
- `PUT /api/integrations/docomator` — сохранить адрес/порт, источник и выбор полей;
- `POST /api/integrations/docomator/check` — проверить доступность и получить пространства/группы/preview;
- `POST /api/integrations/docomator/fields/discover` — получить доступные свойства сотрудников и подсказки для e-mail/должности;
- `POST /api/integrations/docomator/import` — импортировать выбранный список сотрудников и выбранные поля;
- `GET /api/integrations/docomator/people/:personId/fields` — прочитать сохранённые дополнительные свойства конкретного сотрудника.

Изменяющие операции доступны администратору. При отключённой авторизации применяется обычный локальный режим Kafedra Planner.

## Безопасная диагностика соединения

Kafedra Planner различает заранее классифицированные операционные причины и показывает их рядом с кнопкой проверки. Эти коды стабильны и пригодны для журнала эксплуатации:

| Код | Что означает | Что проверить |
| --- | --- | --- |
| `docomator_dns_failed` | имя сервера не разрешается | локальный DNS, `/etc/hosts` или IP-адрес |
| `docomator_connection_refused` | хост найден, но порт отклонил соединение | службу Оформлятора и порт, обычно `8080` |
| `docomator_timeout` | сервер не ответил вовремя | сеть, firewall и загрузку сервиса |
| `docomator_tls_failed` | не удалось установить HTTPS | сертификат, имя узла и выбранный протокол |
| `docomator_wrong_service` | по адресу отвечает другой HTTP-сервис | адрес, порт и reverse proxy |
| `docomator_not_ready` | процесс работает, но база/runtime ещё не готовы | `/readyz` и журнал Оформлятора |
| `docomator_access_denied` | четырёхзначный код не принят | текущий код доступа в Оформляторе |
| `docomator_protocol_error` | ответ несовместим с ожидаемым API | версии обоих приложений |

Неизвестные `5xx` остаются нейтральной внутренней ошибкой. Пользовательскому интерфейсу и сохранённому статусу не передаются PIN, cookie, stack trace, текст исключения, сырой response body или внутренние пути. Ошибка интеграции не блокирует локальный справочник сотрудников и остальные функции кафедры.
