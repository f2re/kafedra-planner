# Массовый импорт научных материалов

## Поддержанные источники

Оператор может загрузить CSV, JSON, XLSX или ODS. Исходный файл сначала сохраняется как обычная неизменяемая версия документа и проходит штатную обработку. Затем система показывает найденные колонки и предлагает сопоставление.

Минимально обязательна колонка с названием. Дополнительно можно указать:

- вид материала;
- авторов;
- DOI;
- год и дату публикации;
- журнал или мероприятие;
- классификации;
- этап жизненного цикла;
- целевое издание;
- следующее действие и срок.

## Частичный успех

Импорт обрабатывает каждую строку в собственной транзакции. Ошибка одной строки не откатывает остальные. Для каждой строки сохраняются исходные данные, нормализованные значения, результат и сообщение:

- добавлено;
- обновлено;
- пропущено как дубликат;
- требуется проверка;
- ошибка.

Журнал `science_import_runs` хранит агрегированные итоги, а `science_import_rows` — доказательство по каждой строке.

## Дубликаты

Приоритет идентификации:

1. нормализованный DOI;
2. нормализованное название и год публикации.

По умолчанию существующая карточка не изменяется. Она отмечается как пропущенная. Обновление разрешается только явным флагом оператора. Тогда изменения сохраняются как ручной override с причиной, а исходная карточка и evidence остаются неизменными.

## Идемпотентность

Запуск имеет `idempotency_key` и хэш документа, сопоставления и настроек. Повтор с теми же параметрами возвращает существующий журнал. Повтор с другими параметрами и тем же ключом завершается понятным конфликтом, не создавая дубликаты.

Если файл уже загружен, а анализ или запуск временно не удался, форма сохраняет `documentId`; повторная попытка не передаёт файл второй раз.

## Доступ

Импортированные научные карточки получают объектную политику исходного документа. Оператор не может использовать импорт для расширения доступа. Журнал доступен только пользователям, которые имеют право читать источник.

## Обновление и восстановление

Схема 23 добавляет только новые таблицы и индексы. Существующие научные карточки, документы, версии и связи не изменяются. Таблицы журнала включаются в release evidence, backup/restore и migration regression.

## API

```text
POST /api/science-imports/analyze
POST /api/science-imports
GET  /api/science-imports
GET  /api/science-imports/:runId
```

## Проверки

Unit/integration покрывают CSV, кавычки, предложенное сопоставление, частичный успех, дубликаты, явное обновление и идемпотентность. Playwright на desktop и mobile проверяет загрузку, предварительный просмотр, сохранение формы при временной ошибке, результат по строкам и отсутствие дублей.
