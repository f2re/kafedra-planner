# Release candidate 0.4.5

## Статус

`0.4.5` — текущий эксплуатационный patch release candidate, схема SQLite **31**. Он выпускает изменения заседаний и массового импорта протоколов после `0.4.4`: нечёткое распознавание структуры, общую правку реквизитов, версии форматов, безопасный повтор и обратимый архив неудачных загрузок. Новая SQLite migration не добавляется. Интернет, LLM, Docker, Оформлятор и облачные сервисы не обязательны для production.

## Что завершено в 0.4.5

- Раздельная повестка и последующие обсуждения сопоставляются по номеру; варианты структурных меток не меняют деловые формулировки. Подпункты решения и подписи не создают лишние вопросы.
- Дата извлекается из шапки каждого загруженного документа, а не из примера. Нулевой день и неоднозначная дата сохраняются как исходный текст без вымышленной календарной даты; остальные данные доступны для работы.
- Общая форма правки реквизитов сохраняет строки независимо и не перезаписывает более новую чужую правку. Исходник и ошибочный ввод остаются рядом.
- Формат распознавания проверяется на образце, сохраняется новой версией и применяется к выбранным документам повторным разбором. Исходники, ручные исправления, перенесённые и удалённые вопросы сохраняются.
- Неотправленный файл можно убрать из списка. Сохранённый файл можно перенести в архив и восстановить; повторная загрузка архивного источника не создаёт копию и не восстанавливает его неявно.
- Архив файла не удаляет уже созданные заседания и решения. Ошибочные вопросы исправляются или удаляются в существующей карточке заседания.
- Перенос вопросов устойчив к повторным запросам и сохраняет связи с планом. DOCX включает все решения, а предыдущие сформированные версии остаются неизменяемыми.

Описание выпуска: [`releases/0.4.5.md`](releases/0.4.5.md). Порядок работы: [`PROTOCOL_IMPORT.md`](PROTOCOL_IMPORT.md).

## Full offline и OCR

Full bundle собирает application runtime, managed Node.js/CPython и air-gap closure для `unzip`, Poppler, Tesseract `rus+eng`, LibreOffice и шрифтов. Target package policy additive-only: ставятся только отсутствующие возможности, без принудительного upgrade/downgrade/remove, без target version pins и без автоматического `apt --fix-broken`.

До переключения `/opt/kafedra-planner/current` выполняются full preflight и реальный `ocr.py doctor --languages rus+eng --self-test`. Ошибка PDF/OCR/Office runtime блокирует активацию нового release. После установки `doctor.sh` проверяет уже активный runtime.

## Сохранность данных

SQLite schema остаётся `31`. Применённые migrations, blobs, SHA-256, `document_version`, source rows и evidence неизменяемы. Ручное рабочее значение не уничтожает machine result. Backup/restore и forced-failure rollback остаются частью release evidence.

## Выпуск

Один version-neutral workflow `Release` запускается только от exact текущего `main`. Project/unit/smoke/backup и critical browser выполняются по одному разу. Затем full offline bundle собирается ровно один раз. Именно этот archive проходит checksum, Debian 12 systemd clean install, repeated update, legacy upgrade и forced rollback. Project Control и семь GitHub Release assets формируются из уже проверенного archive без пересборки.

## Что остаётся до stable

Реальная эксплуатационная приёмка Astra Linux/Debian остаётся в issue #27 и не подменяется CI. Реальная двухдокументная приёмка reusable protocol profile остаётся в issue #326 и не подменяется синтетическими fixtures. Пользователь проверяет реальные документы после установки опубликованного patch-релиза; предварительная пользовательская приёмка не требуется для публикации `0.4.5`.
