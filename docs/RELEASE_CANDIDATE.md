# Release candidate 0.3.4

## Статус

`0.3.4` — текущий эксплуатационный release candidate, схема SQLite **30**. Основные контуры работают автономно и проходят unit/integration, desktop/mobile Chromium, миграционные, backup/restore и full-offline проверки. Stable не объявляется до фактической приёмки на целевых Astra Linux/Debian по [`TARGET_ACCEPTANCE.md`](TARGET_ACCEPTANCE.md) и issue #27.

## Что завершено в 0.3.4

### Обычный DOCX как шаблон заседания

Оператор загружает существующий протокол или выписку без служебных маркеров, визуально назначает поля и повторяемые блоки, проверяет профиль и формирует документ. Рендер сохраняет исходную OOXML-структуру, стили и нумерацию; старые marker-based шаблоны продолжают работать.

### Библиотека шаблонов протоколов и выписок

Каждая форма имеет серию и последовательные версии. Видны готовность, основной статус, автор и статистика использования. Новая версия не меняет существующие заседания. Тестовое заполнение создаёт неизменяемый DOCX с двумя вопросами; локальный PDF-preview необязателен и не может отменить готовый DOCX.

Архивирование показывает влияние, требует причину и готовую замену для основного шаблона. Исходник, профили, исторические заседания и сформированные документы не удаляются. Восстановление возвращает форму в рабочий список. Подробный контракт: [`MEETING_TEMPLATE_LIBRARY.md`](MEETING_TEMPLATE_LIBRARY.md).

### Импорт сотрудников из Оформлятора с выбором полей

После health/readiness/data проверки администратор выбирает пространство и группу. ФИО переносится всегда; источники `E-mail` и `Должность` назначаются явно, дополнительные person-свойства выбираются отдельно. Система предлагает вероятные поля, но не подменяет выбор оператора.

Перед изменением SQLite выбранные ключи сверяются с текущими property definitions. Исчезнувшее поле вызывает понятный конфликт. Remote profiles загружаются до предметной транзакции ограниченным параллелизмом. Связь идемпотентна по `remote employee id`; повторный импорт обновляет запись и не удаляет локальные планы, задачи, отчёты, назначения или историю. Код доступа используется только текущим запросом и не сохраняется. Подробно: [`DOCOMATOR_PEOPLE_IMPORT.md`](DOCOMATOR_PEOPLE_IMPORT.md).

### Адаптивное заполнение ручного плана

Форма предлагает безопасные значения по умолчанию для направления, режима исполнения, исполнителя, контролирующего и относительных дат. Сохранённое значение, дата перехода из календаря и руководитель из оргструктуры имеют приоритет. Обучение учитывает только явные действия после успешного сохранения; абсолютные даты не запоминаются.

## Схема и сохранность данных

- schema `029`: `meeting_template_catalog` и `meeting_template_test_runs`;
- schema `030`: `docomator_field_mappings` и `docomator_person_fields`;
- update проверяется последовательно `28 → 29 → 30`;
- новые таблицы входят в acceptance digest, backup/restore и `quick_check`/`foreign_key_check`;
- исходные DOCX/PDF/XLSX, версии, SHA-256 и audit history не изменяются и не удаляются;
- повторная обработка, тестовая генерация и импорт сотрудников остаются идемпотентными.

## Автономность и поставка

Основной deterministic-контур работает при `KAFEDRA_LLM_ENABLED=false`, без Оформлятора и без Интернета. OCR, LibreOffice, Оформлятор и `llama.cpp` являются дополнительными capabilities; их недоступность не блокирует документы, календарь, планы, поручения или отчёты.

Full bundle использует контракт `full-airgap-v2 / additive-only-v2`: installer не фиксирует версии системных пакетов, не вызывает `apt --fix-broken`, запрещает remove/upgrade существующих пакетов и перед изменяющим обновлением создаёт проверенную резервную копию. Миграция и health-check выполняются до атомарного переключения release; ошибка приводит к rollback.

## Обязательный release-gate

До merge и после merge для точного SHA должны завершиться успешно:

- `npm run check`, полный unit/integration suite и smoke;
- минимальный Node 24.15 и разделение host Node 25/runtime Node 24;
- миграции до schema 30, acceptance digest, backup/restore и rollback;
- desktop/mobile сценарии планов, заседаний, библиотеки шаблонов, Оформлятора, науки, `План / факт`, PIN/auth и ACL;
- полный Debian 12 bundle;
- реальная offline systemd-установка;
- offline `llama.cpp`/GGUF установка с проверкой ядра после отключения LLM;
- F2RE Project Control update и контрольные суммы.

Publisher не доверяет одному top-level conclusion: он проверяет фактические jobs. Реальная failure/cancelled/unexpected skipped останавливает выпуск и не повторяется автоматически. Перед публикацией повторно проверяется точный `main` SHA.

## Что остаётся до stable

На реальной Astra Linux и контрольной Debian необходимо подтвердить:

- чистую установку `0.3.4`, первый PIN-flow и работу desktop/mobile;
- обновление существующей базы `0.3.3 / schema 28` до `0.3.4 / schema 30`;
- сохранность документов, планов, поручений, связей Оформлятора, профилей/версий шаблонов и evidence после backup/restore;
- forced rollback после искусственно сорванного update;
- vendor revisions пакетов Astra, systemd hardening и права каталогов;
- реальные Tesseract/Poppler/LibreOffice на ведомственных документах;
- при доступном Оформляторе — настоящий импорт выбранных полей без сохранения кода;
- при использовании LLM — настоящий `llama-server`/GGUF и работа ядра после его отключения.

До подписанного акта #27 проект остаётся release candidate независимо от состояния CI.
