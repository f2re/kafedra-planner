# Release candidate 0.1.0-rc.1

## Назначение

Версия переводит систему из функциональной alpha-стадии в эксплуатационный
release candidate. Основной критерий — повседневная работа кафедры не требует
ручного вмешательства разработчика для создания аккаунтов, контроля сессий и
проверки безопасности конфигурации.

## Перед обновлением

1. Создайте резервную копию SQLite-базы и каталога `data/blobs`.
2. Проверьте наличие хотя бы одного активного административного аккаунта.
3. Для HTTPS установите `KAFEDRA_AUTH_SECURE_COOKIES=true`.
4. Не отключайте `KAFEDRA_AUTH_CSRF_ENABLED=true`.
5. Выполните миграции штатным установочным или обновляющим скриптом.

## После обновления

Администратор открывает меню пользователя → «Управление доступом» и проверяет:

- состояние авторизации;
- наличие активного администратора;
- включённую CSRF-защиту;
- режим cookie;
- список сотрудников без аккаунтов;
- активные сессии.

## CSRF

Каждая серверная сессия получает отдельный CSRF-токен. Браузер автоматически
добавляет его в изменяющие запросы. Запрос без токена получает HTTP 403.
Токен не используется как пароль и меняется вместе с серверной сессией.

## Иерархия

Руководитель видит не только прямых подчинённых, но и всю вложенную цепочку
до 32 уровней. Рекурсивный запрос защищён от циклов в справочнике.

## Аварийное завершение сессий

Администратор может:

- завершить отдельную сессию;
- завершить все сессии выбранного аккаунта;
- завершить все сессии рабочего пространства, сохранив текущую.

Все действия фиксируются в журнале `auth_audit_events`.
