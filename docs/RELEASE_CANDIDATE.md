# Release candidate 0.4.0

## Статус

`0.4.0` — текущий эксплуатационный release candidate, схема SQLite **31**. Выпуск добавляет законченный контур ведомостей и успеваемости, не меняя автономный контракт: Интернет, LLM, Docker, Оформлятор и внешние облачные сервисы не обязательны. Stable не объявляется до фактической приёмки на целевых Astra Linux/Debian по [`TARGET_ACCEPTANCE.md`](TARGET_ACCEPTANCE.md) и issue #27.

## Что завершено в 0.4.0

### Ведомость как проверяемый источник

Оператор загружает XLSX, ODS или CSV через штатный document intake. Исходный blob, версия документа и SHA-256 остаются неизменяемыми. Система определяет лист, строку заголовков, колонку ФИО и дисциплины; оператор исправляет только неоднозначности.

### Метаполя из ячейки или ручного ввода

Учебная группа, учебный год и семестр задаются двумя явными способами:

- точная ячейка выбранного листа;
- ручное значение.

Для ячеечного значения сервер повторно читает исходную версию и сохраняет raw value, normalized value, лист, адрес, locator и правило нормализации. Ручному значению не назначается фиктивная координата.

### Иерархия периодов и версии

Рабочий экран организован как `учебный год → семестр → группа`. Для пары `группа + период` только последняя успешно обработанная ведомость участвует в сводке. Новая успешная версия переводит прежнюю в историю; неуспешная не вытесняет готовую. Архивирование и восстановление обратимы.

### Сводка и выгрузка

По каждой группе и дисциплине выводятся количества `отлично`, `хорошо`, `удовлетворительно`, `неудовлетворительно`, `не аттестован`, число значений для проверки и средний балл. Пустая ячейка не считается неаттестацией. Средний балл рассчитывается по исходным оценкам `2–5`, а не по средним групп.

CSV, JSON и `sources.json` используют ту же фильтрованную серверную выборку. Детализация раскрывает студента, версию документа, лист и адрес исходной ячейки.

## Схема и сохранность данных

- schema `031`: группы, периоды, студенты, составы групп, дисциплины, импорты, метаполя, оценки и проблемы разбора;
- update проверяется `30 → 31` без изменения существующих устойчивых данных;
- уникальный partial index гарантирует одну текущую ведомость группы/периода;
- ошибка строки или ячейки не блокирует остальные данные;
- повтор импорта идемпотентен;
- новые таблицы входят в backup/restore, logical digest, `quick_check` и `foreign_key_check`;
- существующие документы, планы, заседания, научный реестр, связи Оформлятора и история не удаляются.

## Сохранённые возможности 0.3.4

Визуальные DOCX-шаблоны заседаний, библиотека версий, выбор полей Оформлятора, адаптивные defaults ручных планов, PIN, ACL, backup/restore, transactional update и full-offline package contract остаются частью обязательной регрессии.

## Обязательный release-gate

До merge и после merge для точного SHA должны завершиться успешно:

- `npm run check`, полный unit/integration suite и smoke;
- минимальный Node 24.15 и разделение host/runtime;
- миграция `30 → 31`, academic integration и backup/restore;
- desktop/mobile сценарий загрузки ведомости, выбора метаполей, иерархии, сводки и источника;
- все прежние browser-контуры планов, заседаний, Оформлятора, науки, PIN/auth и ACL;
- полный Debian 12 bundle, systemd install/update/rollback и F2RE Project Control package.

Failure, cancelled, pending или неожиданно skipped не считаются зелёным результатом. Publisher перед тегированием повторно подтверждает точный SHA `main`.

## Что остаётся до stable

На реальной Astra Linux и контрольной Debian необходимо подтвердить:

- чистую установку `0.4.0`, первый PIN-flow и desktop/mobile;
- обновление `0.3.4 / schema 30 → 0.4.0 / schema 31`;
- импорт реальной ведомости XLSX/ODS/CSV, метаполя из ячейки и сводную выгрузку;
- сохранность всех документов, ведомостей, истории версий и evidence после backup/restore;
- forced rollback после искусственно сорванного update;
- vendor revisions, systemd hardening и реальные OCR/LibreOffice capabilities.

До подписанного акта #27 проект остаётся release candidate независимо от состояния CI.
