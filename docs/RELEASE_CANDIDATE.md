# Release candidate 0.4.12

## Статус

`0.4.12` — текущий номер исходного пакета. Тег `v0.4.12` содержит схему SQLite **31** и описанный ниже поиск протоколов; текущий `main` после тега использует схему **33**: месячные составы, визуальные шаблоны мероприятий и проверяемый подбор для кафедры. На 11 ноября 2026 года последний опубликованный GitHub Release с установочными assets — [`v0.4.7`](https://github.com/f2re/kafedra-planner/releases/tag/v0.4.7); Release для `v0.4.12` не опубликован. Сборка из текущего исходного кода и опубликованный установщик — разные артефакты. Интернет, LLM, Docker, Оформлятор и облачные сервисы не обязательны для production.

## Что изменено в 0.4.12

- Естественно-языковой поиск протоколов через LLM-ассистента по сложным запросам (например, «На каком заседании кафедры обсуждалась статья о влажности и какие решения были приняты?»).
- Выделение существенных терминов (`extractSubstantiveQuery`), исключающее вопросительные и вводные обороты из поискового фильтра.
- Морфологический стемминг русских корней (`searchStem`) в SQLite FTS5 для нечувствительности к падежным окончаниям.
- Гидратация кандидатов полным текстом фрагментов (`content` до 2500 знаков) вместо 24-токенных сниппетов.
- Верификация цитат с нормализацией переносов строк (`normQuote`) и зелёный бейдж `✓ Подтверждено` в интерфейсе.
- Сохранение `quorum_required` в базе данных при создании и слиянии протоколов в `persistProtocol`.
- Полнотекстовая индексация присутствующих (`attendees_raw`), кворума и решений в `syncMeetingSearch` с сохранением при последующих редактированиях.
- Защита детерминированно извлечённых списков участников от перезаписи в Worker.

Описание выпуска: [`releases/0.4.12.md`](releases/0.4.12.md). Контракты: [`MEETINGS.md`](MEETINGS.md).

## Full offline и OCR

Каждый target bundle содержит приложение, managed Node.js/CPython и air-gap closure для `unzip`, Poppler, Tesseract `rus+eng`, LibreOffice и шрифтов. Target package policy additive-only: ставятся только отсутствующие возможности, без принудительного upgrade/downgrade/remove, без target version pins и без автоматического `apt --fix-broken`.

До переключения `/opt/kafedra-planner/current` выполняются full preflight и реальный `ocr.py doctor --languages rus+eng --self-test`. Ошибка PDF/OCR/Office runtime блокирует активацию нового release. После установки `doctor.sh` проверяет уже активный runtime.

## Сохранность данных

Текущий `main` содержит migrations до **033** включительно. Применённые migrations, blobs, SHA-256, `document_version`, source rows и evidence неизменяемы. Ручное рабочее значение не уничтожает machine result. Backup/restore и forced-failure rollback остаются частью release evidence. Приёмка #377 не меняет schema/storage; проверку перехода 32→33 выполнила реализация #375.

## Выпуск

Один version-neutral workflow `Release` запускается только от exact текущего `main`. Project/unit/smoke/backup и critical browser выполняются по одному разу; отдельный smoke проверяет минимальный Node.js `24.15.0`. Для каждой из трёх ОС archive собирается один раз. Astra UBI проверяет пакетный слой и OCR/Office; Debian 12 — systemd clean install, repeated update, legacy layout и обновление предыдущего опубликованного выпуска с forced rollback. Из тех же архивов создаются Project Control packages; публикуются 15 файлов, включая контрольные суммы, без пересборки.

## Что остаётся до stable

Реальная эксплуатационная приёмка Astra Linux/Debian остаётся в issue #27 и не подменяется CI или UBI. Реальная двухдокументная приёмка reusable protocol profile остаётся в issue #326 и не подменяется синтетическими fixtures. Полезность конкретной ЛЛМ и скорость на целевом CPU проверяются на реальном обезличенном корпусе отдельно от тестов интеграции. Перед следующим выпуском выбирается новая версия и выполняется единый release workflow от exact `main`; прежние теги и assets не перезаписываются.
