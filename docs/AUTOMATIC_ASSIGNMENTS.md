# Автоматическое назначение поручений из плана

Пункт импортированного плана не требует повторного ручного создания поручения, если система уже однозначно знает исполнителя.

## Правило

После детерминированного разбора плана исходное значение `responsible_raw` всегда сохраняется вместе с evidence. Затем выполняется только безопасное точное сопоставление по нормализованному ФИО активного сотрудника.

Если совпадение найдено однозначно:

- `responsible_person_id` связывается с сотрудником;
- пункт получает режим `assigned`;
- через существующий уникальный `plan_item_assignments` создаётся одно поручение;
- основной исполнитель — найденный сотрудник;
- контролирующий берётся из основного назначения сотрудника на дату контрольного срока/начала задачи, затем из совместимого legacy `manager_id`;
- исходное ФИО из документа не заменяется нормализованным значением и остаётся доказательством;
- в evidence поручения фиксируются правило сопоставления и источник определения контролирующего.

Если совпадения нет, строка остаётся контрольной точкой `track`. Система не угадывает человека по похожему имени и не создаёт предметный факт из статистики интерфейса.

## Идемпотентность и история

Один пункт плана может иметь не более одного связанного поручения. Повторная обработка той же версии документа возвращает существующий план и не создаёт новое поручение. Уже созданное, представленное или завершённое поручение повторным импортом не переназначается и не удаляется.

Ручной разбор исходной строки остаётся явной операцией оператора: можно разделить строку на несколько задач, поменять исполнителей или контролирующего. Это уже подтверждённое пользовательское изменение и не считается автоматической синхронизацией.

## Интерфейс

В плане рядом с ответственным показывается состояние `Назначен`, `Предлагается назначить` или `Нужно уточнить сотрудника`. В общем разделе «Поручения» задания без распоряжения, созданные из пункта плана, помечаются как `поручение из плана` и открываются через существующий инспектор исполнения/отчёта.

Форма новой периодической задачи не занимает рабочий экран постоянно: она раскрывается отдельной кнопкой. Это не меняет предметную модель периодических задач и совместимо с обучаемыми значениями из `ui_choice_preferences`.

## Граница адаптивного UX

Определение сотрудника и руководителя из подтверждённого справочника/оргструктуры — `domain-derived`. Оно сильнее статистических предпочтений. Статистика интерфейса может подставлять только разрешённые безопасные значения и никогда не создаёт назначение сама.
