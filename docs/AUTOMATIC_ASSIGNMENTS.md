# Автоматическое назначение задач из плана

Пункт импортированного плана не требует повторного ручного создания задачи, если система уже однозначно знает исполнителя.

## Правило

После детерминированного разбора плана исходное значение `responsible_raw` всегда сохраняется вместе с evidence. Затем выполняется только безопасное точное сопоставление по нормализованному ФИО активного сотрудника.

Если совпадение найдено однозначно:

- `responsible_person_id` связывается с сотрудником;
- пункт получает режим `assigned`;
- через существующий уникальный `plan_item_assignments` создаётся одна задача;
- основной исполнитель — найденный сотрудник;
- контролирующий при наличии берётся из основного назначения сотрудника на дату контрольного срока/начала задачи, затем из совместимого legacy `manager_id`;
- исходное ФИО из документа не заменяется нормализованным значением и остаётся доказательством;
- в evidence фиксируются правило сопоставления и источник определения контролирующего.

Если совпадения нет, пункт всё равно создаётся. Система не угадывает человека по похожему имени: сохраняет исходное ФИО и оставляет назначение доступным для редактирования оператором.

## Идемпотентность и история

Один пункт плана может иметь не более одной связанной задачи. Повторная обработка той же версии документа возвращает существующий план и не создаёт новое поручение. Уже созданная, отредактированная или завершённая задача повторным импортом не переназначается и не удаляется молча.

Ручной разбор исходной строки остаётся явной операцией оператора: можно разделить строку на несколько задач, поменять даты, исполнителей или контролирующего. Исходная строка и её локаторы сохраняются.

## Выполнение

Назначенная задача сразу доступна в общем разделе работы и календаре. Для завершения достаточно действия `Выполнено`. Подтверждение руководителем не требуется.

Подтверждающий документ можно приложить до или после выполнения. Он необязателен и не меняет состояние задачи. Повторная привязка того же документа не создаёт второй evidence.

Подробно: [`SIMPLE_COMPLETION.md`](SIMPLE_COMPLETION.md).

## Интерфейс

В плане рядом с ответственным показывается состояние `Назначен`, `Предлагается назначить` или `Нужно уточнить сотрудника`. Задача из пункта плана открывается через общий инспектор, где видны источник, исполнитель, срок, прогресс, одно действие `Выполнено` и необязательные подтверждающие материалы.

Форма новой периодической задачи не занимает рабочий экран постоянно: она раскрывается отдельной кнопкой. Это не меняет предметную модель периодических задач и совместимо с обучаемыми значениями из `ui_choice_preferences`.

## Граница адаптивного UX

Определение сотрудника и руководителя из подтверждённого справочника/оргструктуры — `domain-derived`. Оно сильнее статистических предпочтений. Статистика интерфейса может подставлять только разрешённые безопасные значения и никогда не создаёт назначение сама. Завершение, архивирование и переназначение относятся к `never-learn`.
