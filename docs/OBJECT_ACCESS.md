# Объектные права доступа

Роль `staff / manager / admin` задаёт общий уровень полномочий, но не открывает автоматически все данные рабочего пространства. Документы и предметные сущности проходят серверную object access policy.

## Безопасное правило по умолчанию

Новая ограниченная загрузка имеет владельца из текущей серверной сессии и не получает неявной публичной видимости. Клиент не может назначить себе владельца или расширить область доступа заголовком/`personId`.

Если доступ к старому объекту нельзя безопасно вывести при миграции, он остаётся ограниченным, а не становится публичным.

## Роли объекта

| Роль | Чтение | Изменение | Контроль | Изменение ACL через текущий admin API |
|---|---:|---:|---:|---:|
| reader | да | нет | нет | нет |
| editor | да | да | нет | нет |
| controller | да | да | да | нет |
| owner | да | да | да | нет |
| admin | да | да | да | да |

## Предметное наследование

Права вычисляются по реальным связям, а не размножаются как статические grants на каждого руководителя.

- отчёт наследует рабочие связи поручения;
- распоряжение доступно исполнителям/контролирующим через свои предметные отношения;
- научный материал доступен связанным авторам и разрешённой руководительской зоне;
- imported plan наследует политику исходного документа;
- manual plan имеет собственную object policy;
- исполнитель связанного plan assignment получает доступ к поручению, но не автоматически ко всему закрытому плану;
- supporting document читается через разрешённый связанный объект, не расширяя права на остальные связи;
- руководительская область определяется сервером рекурсивно по актуальной модели.

## Единая точка проверки

Одна политика применяется к:

- спискам и карточкам документов;
- original/preview/structured source;
- plans/plan items и календарным проекциям;
- directives/assignments/reports;
- meetings и связанным документам;
- scientific items;
- search/FTS/facets;
- review queues;
- supporting documents.

Знание ID или прямого URL не обходит list filtering.

## Ответ при запрете

Существующий объект без права доступа возвращает общий `403` без названия, filename, checksum, blob path или других закрытых метаданных. Отсутствующий объект возвращает `404`.

## Административный API

Примеры чтения объяснения политики:

```text
GET /api/admin/access/document/<id>
GET /api/admin/access/directive/<id>
GET /api/admin/access/scientific_item/<id>
```

Изменение политики выполняется только авторизованным admin request с CSRF и записывается в аудит.

## Проверка

В source checkout:

```bash
npm run test:browser:acl
```

Browser test проверяет прямой URL, list/search leakage, доступ сотрудника к своему объекту, запрет чужого и руководительскую зону. На target дополнительно выполняется целевая процедура [`TARGET_ACCEPTANCE.md`](TARGET_ACCEPTANCE.md).
