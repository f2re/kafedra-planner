# Работа оператора с планами

## Назначение

Раздел `Планы` объединяет готовые планы работы, их пункты, календарные сроки и формирование следующего плана по существующему DOCX-образцу. Он не заменяет раздел `План/факт`: здесь хранится содержание нормативного/рабочего плана и его происхождение, а не отчёт о выполнении показателей.

## Загрузка готового плана

Оператор открывает `Планы` → `Загрузить план` и выбирает DOCX, ODT, XLSX, ODS, PDF или TXT. Файл проходит обычный document intake: оригинал сохраняется неизменяемо, обработка выполняется worker и не блокирует интерфейс.

После разбора система показывает план и все распознанные пункты. Для каждого пункта видны:

- номер и мероприятие;
- дата/период или контрольный срок;
- ответственный;
- направление;
- ожидаемый результат;
- локатор исходной строки, таблицы, листа или страницы.

Строки без надёжного срока остаются в плане, но не получают выдуманную календарную дату.

## Фильтры

Список планов фильтруется по:

- тексту;
- виду плана;
- календарному/учебному году;
- направлению;
- ответственному.

Кнопка `Сбросить` очищает весь набор условий. Фасеты строятся только по объектам, доступным текущему пользователю.

## Исправление неоднозначного пункта

Кнопка `Исправить` открывает компактную форму рядом с рабочим сценарием. Можно уточнить название, начало/окончание, контрольный срок, ответственного, направление и ожидаемый результат.

Ключевое правило: `evidence_json` исходного извлечения не переписывается. Коррекция записывается в `audit_log` с предыдущим и новым состоянием, причиной и локатором исходного доказательства.

После сохранения в одной транзакции пересчитываются только производные данные этого пункта:

- календарные записи;
- FTS-фрагмент;
- фасеты;
- вопрос проверки о пунктах без срока.

Если последний пункт без срока получил дату, существующий вопрос проверки закрывается. Если коррекцию отменить и неоднозначность вернётся, тот же вопрос открывается снова — новый дубль не создаётся.

После изменения интерфейс предлагает `Отменить`. Отмена восстанавливает предыдущий снимок из журнала, повторно строит производные данные и оставляет отдельную запись аудита.

## Формирование следующего плана

Если исходный план — DOCX, его можно использовать как образец. Система анализирует:

- подпись учебного/календарного года;
- таблицу мероприятий;
- строку-образец;
- назначение колонок.

Однозначная структура сохраняется как шаблон автоматически. Если найдено несколько подходящих годов или таблиц, оператор выбирает правильный кандидат. Неизвестные колонки никогда не очищаются молча: для этого требуется явное подтверждение.

При действии `Сформировать новый`:

1. по умолчанию выбирается следующий календарный или учебный год;
2. даты пунктов переносятся на соответствующий следующий год;
3. оператор видит и может поправить строки до выпуска документа;
4. год меняется только в подтверждённых OOXML-якорях;
5. строка таблицы клонируется вместе со стилями Word;
6. формируется новый DOCX;
7. DOCX регистрируется обычным document intake и снова разбирается worker;
8. полученный план и его сроки появляются в реестре и календаре.

Генерация идемпотентна: одинаковый запрос получает устойчивый ключ по шаблону и содержимому. Повтор не создаёт второй документ.

## Источник в календаре

Календарная запись из плана показывает человекочитаемый источник, например `План кафедры · 2027/28`. Из инспектора можно открыть план, а из карточки плана — исходный документ.

Изменение даты в календаре остаётся отдельной календарной ревизией. Исправление самой строки плана выполняется через раздел `Планы`, чтобы производные представления оставались согласованными.

## Доступ

План, его пункты, коррекции и сформированные документы не расширяют права исходного документа. Чтение и изменение проверяются через объектный ACL исходника. Сформированный DOCX наследует его политику доступа.

## Проверки

Приёмочный контур включает:

- unit-тест обратимой коррекции с проверкой неизменности `evidence_json`;
- проверку FTS, фасетов, календаря и review после correction/undo;
- Playwright desktop/mobile: DOCX → план → следующий период → сформированный DOCX → календарь → источник;
- Playwright desktop/mobile: готовый план → строка без срока → исправление → отмена;
- полную существующую browser-регрессию календаря, документов, ACL, авторизации, отчётов и план/факта.
