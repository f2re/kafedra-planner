# Распорядительные документы, поручения и отчётность

## Главная модель

```text
указ / распоряжение / приказ
→ поручение
→ исполнители и контролирующий
→ срок и календарь
→ прогресс
→ отчётный документ
→ подтверждение руководителем / возврат
→ план / факт
```

Исходный PDF/DOCX остаётся неизменяемым. Номер, дата, вид основания, текст пункта, сроки, исполнители и другие автоматически извлечённые значения сохраняются вместе с evidence и могут быть исправлены оператором только отдельной ревизией.

## Deterministic режим

Основной поток полностью работает без LLM:

- определение вида документа по проверяемым признакам;
- извлечение номера и даты;
- поиск распорядительных секций;
- разбиение пунктов;
- извлечение сроков, ответственных и ожидаемого результата;
- сопоставление сотрудников;
- вопросы проверки для реальной неоднозначности.

Ошибка одного пункта или отсутствие части реквизитов не блокирует обработку остальных результатов.

## Опциональный llama.cpp

LLM вызывается только как дополнительный локальный кандидат и не имеет права молча заменить подтверждённый факт. Основная конфигурация:

```text
KAFEDRA_LLM_ENABLED=false
KAFEDRA_LLM_ENDPOINT=http://127.0.0.1:8081
KAFEDRA_LLM_MODEL=local-model
KAFEDRA_LLM_TIMEOUT_MS=45000
KAFEDRA_LLM_MAX_TOKENS=4096
```

Managed offline `llama.cpp`/GGUF поставка описана в [`LLAMA_OFFLINE_DEPLOYMENT.md`](LLAMA_OFFLINE_DEPLOYMENT.md). Предметный контракт LLM: [`DIRECTIVES_AND_LLM.md`](DIRECTIVES_AND_LLM.md).

## Поручение

Поручение хранит основание, исполнителей, контролирующего, срок, ожидаемый результат, состояние и историю прогресса. Оно может быть создано не только из распоряжения, но и из пункта ручного плана. Поручение из плана не обязано иметь `directive_id`.

## Отчёт и подтверждение

Отчёт остаётся самостоятельным документом. Связь с поручением хранится отдельно. Возможны несколько отчётов/ревизий. Руководитель подтверждает результат либо возвращает его на доработку; возврат не уничтожает уже представленные документы или историю.

Подтверждение синхронизирует рабочее состояние и `План / факт`. Для поручения, созданного из пункта плана, также синхронизируются пункт и календарная задача.

## Периодические обязанности

Семестровая/годовая/квартальная задача хранит исполнителя, руководителя, период, плановый и контрольный сроки, направление, ожидаемый результат и требование отчёта. Уведомления идемпотентны и не должны спамить дубликатами одной версии срока.

## Поиск

Документы, поручения, планы, отчёты и научные материалы используют общий слой полнотекстового поиска и фасетов. Видимые фильтры не являются отдельным источником данных и не расширяют ACL объектов.
