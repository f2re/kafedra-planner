# Кафедра Planner

Автономная рабочая система кафедры: календарь, задачи, документы, решения, сроки, планы, научная и педагогическая деятельность.

Система сохраняет исходный документ, извлекает проверяемые сведения, связывает их с календарём и поиском и показывает оператору только те вопросы, которые нельзя решить надёжно автоматически.

> Текущий статус: **release candidate `0.1.0-rc.3`**. Основные рабочие контуры, планы, локальная авторизация, проверяемые резервные копии и автоматический откат обновления реализованы; перед стабильным релизом остаются общие объектные права, внешняя доставка уведомлений и целевая эксплуатационная приёмка Astra Linux/Debian.

## Что видит оператор

После открытия системы сразу показывается календарь текущего месяца.

```text
Календарь месяца
├─ переключение: месяц / неделя / задачи
├─ события и контрольные сроки
├─ записи на сегодня и ближайшие семь дней
├─ центр уведомлений
├─ создание события или задачи в одном листе
└─ переход к документу, плану, шаблону или вопросу проверки
```

На мобильном экране боковая панель заменяется нижними вкладками. На большом экране её можно скрыть, чтобы календарь занимал всю ширину.

## Что уже работает

### Календарь и задачи

- основной экран — текущий месяц;
- недельное представление;
- список задач с группами `Просрочено`, `Сегодня`, `Предстоящие`, `Выполнено`;
- ручные события и задачи;
- категории: наука, образование, организация, повседневная работа;
- важность и комментарии;
- завершение и возврат задачи;
- напоминания в день события, за час, день, три дня или неделю;
- серверное состояние уведомлений: прочитано и скрыто;
- автоматические задачи из сроков решений протокола;
- события и контрольные сроки из планов с видимым источником.

### Документы

- потоковая загрузка одного или нескольких файлов;
- неизменяемое blob-хранилище и дедупликация по SHA-256;
- версии документов;
- фоновая обработка, переживающая закрытие страницы и перезапуск worker;
- TXT, Markdown, CSV, JSON, DOCX, ODT и PDF;
- структурные ячейки DOCX, ODT/ODS и XLSX;
- автоматическое определение протокола заседания;
- номер, дата, председатель, секретарь, присутствующие, повестка и решения;
- ответственные и сроки;
- доказательство происхождения: версия документа и локатор исходного фрагмента;
- полнотекстовый поиск.

### Планы

Планы являются отдельным предметным контуром и остаются связанными с исходным документом.

Поддерживается:

- загрузка готового плана кафедры, факультета, подразделения, организации или личного плана;
- автоматическое определение вида плана и календарного/учебного года;
- разбор строк таблицы: мероприятие, дата или период, контрольный срок, ответственный, направление и ожидаемый результат;
- сохранение доказательства по строке или ячейке исходного документа;
- автоматическое создание событий, задач и сроков в календаре без дублей при повторной обработке;
- подпись источника у календарной записи: вид плана, период и исходный документ;
- фильтрация планов по виду, году, направлению и ответственному;
- изоляция личных планов: сотрудник видит свои, руководитель — планы своей иерархии;
- строки без надёжной даты или сотрудника не блокируют импорт остальных пунктов, а попадают в очередь проверки.

#### Формирование по DOCX-образцу

Оператор загружает DOCX-образец один раз. Система автоматически ищет год, таблицу мероприятий, строку заголовка и строку-образец. Настройки можно исправить перед сохранением шаблона.

При создании нового плана:

```text
шаблон DOCX
→ выбрать год / учебный год
→ заполнить строки плана
→ сформировать DOCX с оформлением образца
→ штатный повторный разбор
→ план и сроки в календаре
```

Год подставляется автоматически. Для строк таблицы используется стиль исходной строки-образца. Сформированный DOCX регистрируется как обычный неизменяемый документ и проходит тот же worker-конвейер, что загруженный файл.

### Шаблоны извлечения

Оператор может один раз настроить новый вид документа:

```text
обработанный документ
→ щелчок по строке
→ название и тип поля
→ правило извлечения
→ проверка результата
→ сохранение шаблона
→ автоматическая обработка следующих документов
```

Поддерживаются правила:

- значение после подписи в той же строке;
- следующая непустая строка;
- вся строка;
- текст между двумя подписями.

Типы значений:

- короткий и длинный текст;
- дата;
- число;
- да / нет.

Шаблон хранит источник, поля, обязательность, правила сопоставления и доказательства. Если обязательное поле не найдено, уже извлечённые данные не теряются: система создаёт один понятный вопрос оператору.

## Основные пользовательские сценарии

Полный UX-контракт и критерии приёмки находятся в [`docs/UX_FLOWS.md`](docs/UX_FLOWS.md).

Ключевые правила:

- система сразу открывает основную работу, а не сводную панель;
- переключение представления не меняет раздел;
- обратимые действия не требуют лишних подтверждений;
- ошибки и статус показываются рядом с объектом;
- модальные предупреждения используются только для действительно критических ситуаций;
- фоновая обработка не блокирует календарь;
- каждый новый сценарий получает автоматический тест потока.

## Инспектор и обратимые изменения

Календарная запись и документ открываются в правой инспекторной панели без ухода с текущего экрана. На мобильном устройстве та же панель становится нижним листом.

- событие можно просмотреть, изменить и завершить из одного места;
- автоматическая запись показывает исходный документ;
- событие из плана показывает вид плана, период и переход к исходному плану;
- документ показывает извлечённые поля, доказательства по строкам, протоколы и вопросы проверки;
- событие можно перенести на другой день перетаскиванием;
- перенос записывается в журнал и восстанавливается кнопкой `Отменить`;
- фильтры категорий и типа записи сохраняются между сеансами;
- черновик мастера шаблона сохраняется на сервере и восстанавливается после закрытия браузера.

## Почему Node.js

Для платформенного ядра используется **Node.js 24 LTS** и стандартные модули Node.js без обязательных runtime-зависимостей npm.

Это даёт:

- один runtime для API, worker, OOXML и интерфейса;
- простую автономную поставку под Astra Linux;
- потоковую работу с файлами;
- встроенные SQLite и тестовый runner;
- возможность подключать Python только как специализированный адаптер для OCR, ML или научных расчётов.

DOCX и ODT читаются из OOXML/XML через системный `unzip`. Генератор планов также работает непосредственно с OOXML и стандартным `node:zlib`, без новой runtime-библиотеки. PDF преобразуется `pdftotext`. LibreOffice и OCR подключаются отдельными адаптерами. Генеративная модель не является обязательной частью конвейера.

## Почему SQLite на первом этапе

SQLite находится только на сервере. Пользователи работают через HTTP API и не открывают файл базы по сети.

Для одной кафедры это обеспечивает:

- минимальный автономный комплект;
- транзакции, WAL и внешние ключи;
- FTS5;
- простое резервирование;
- меньше эксплуатационных отказов.

Слой хранения изолирован предметными сервисами. Переход на PostgreSQL предусматривается при появлении нескольких подразделений, высокой конкуренции записи, репликации или тяжёлой аналитики.

## Быстрый запуск

Требуется Node.js `24.15+`. Для DOCX/ODT нужен `unzip`, для PDF — `pdftotext` из `poppler-utils`.

```bash
mkdir -p data
npm run migrate
npm start
```

В отдельном терминале:

```bash
npm run worker
```

Откройте:

```text
http://127.0.0.1:8080
```

Для другого порта:

```bash
KAFEDRA_PORT=8090 npm start
```

## Структура проекта

```text
apps/
  api/                 HTTP API и статический интерфейс
  worker/              фоновая обработка документов
packages/
  calendar/            события, задачи, напоминания
  config/              конфигурация
  core/                ошибки, идентификаторы, журналирование
  document-intake/     форматы, blob-хранилище, извлечение текста
  plans/               разбор планов и DOCX-формирование по образцу
  protocols/           разбор и сохранение протоколов
  storage/             SQLite, миграции, очередь, поиск
  templates/           шаблоны и детерминированное извлечение
public/                 операторский интерфейс
migrations/             последовательные SQL-миграции
deploy/                 systemd, nginx, установка
scripts/offline/        автономный комплект
docs/                   архитектура, UX-контракт и план развития
```

## Структурный источник документа

Адресуемые фрагменты исходника сохраняются отдельно от машинных результатов:

- абзацы и ячейки DOCX;
- абзацы и ячейки ODT/ODS;
- листы и ячейки XLSX;
- страницы и координаты текстового слоя PDF;
- строки текстовых файлов.

В инспекторе оператор может показать доказательство конкретного поля, выбрать другой фрагмент и сохранить ручное исправление. Машинный результат при этом не стирается: исправление хранится отдельной ревизией с причиной и выбранным источником.

Подробности: [`docs/STRUCTURED_DOCUMENTS.md`](docs/STRUCTURED_DOCUMENTS.md).
