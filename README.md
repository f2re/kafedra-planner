# Кафедра Planner

Автономная система для учёта документов, решений, сроков, научной и педагогической деятельности кафедры.

Это не папка с файлами и не отдельный «парсер протоколов». Платформа сохраняет исходный документ, извлекает проверяемые сведения, связывает их с календарём и поиском и показывает оператору только те вопросы, которые нельзя решить надёжно автоматически.

> Текущий статус: **архитектурный прототип `0.1.0-alpha.1`**. Уже работает сквозной путь «загрузка документа → фоновая обработка → протокол → решения → календарь → поиск → очередь проверки». Авторизация, визуальный редактор шаблонов и производственная приёмка Astra Linux ещё не завершены.

## Что уже работает

- потоковая загрузка одного или нескольких файлов через веб-интерфейс;
- неизменяемое файловое хранилище с дедупликацией по SHA-256;
- версии документов и отдельные состояния обработки;
- устойчивая очередь заданий в SQLite с арендой, повтором и восстановлением после перезапуска;
- извлечение текста из TXT, Markdown, CSV, JSON, DOCX, ODT и PDF;
- автоматическое определение протокола заседания кафедры;
- извлечение номера, даты, председателя, секретаря, присутствующих, пунктов повестки и решений;
- выделение ответственных и сроков из решений;
- автоматическое создание событий заседаний и контрольных сроков;
- полнотекстовый поиск по исходным документам, заседаниям и решениям;
- происхождение сведений: версия документа и диапазон строк;
- единая неблокирующая очередь проверки;
- операторский интерфейс: обзор, документы, календарь, проверка и поиск;
- JSON API, системная диагностика, структурированные журналы;
- systemd-шаблоны и основа автономного комплекта для Astra Linux.

## Основной сценарий

```text
Пачка документов
→ сохранение оригиналов
→ определение формата
→ фоновое извлечение текста
→ определение типа документа
→ разбор протокола
→ заседание и пункты повестки
→ решения и сроки
→ календарь и поиск
→ компактная очередь проверки
```

Один повреждённый или неизвестный файл не блокирует остальные. Исходный документ не изменяется. Неподтверждённое значение не выдаётся за достоверный факт.

## Почему Node.js

Для первой платформенной версии выбран **Node.js 24 LTS** и стандартные модули Node.js без обязательных runtime-зависимостей npm.

Причины:

- один runtime для API, worker, обработки OOXML и интерфейса;
- уже проверенный подход в `docomator`;
- простой автономный комплект: приложение и один закреплённый runtime;
- потоковая работа с большими файлами;
- удобная модульная композиция и встроенные тесты;
- возможность подключать специализированные Python-процессы через стабильный адаптер, не меняя ядро.

DOCX и ODT читаются напрямую из OOXML/XML через системный `unzip`. PDF преобразуется `pdftotext`. LibreOffice и OCR будут отдельными адаптерами. Генеративная модель не является обязательной частью конвейера.

## Почему SQLite на первом этапе

SQLite находится **только на сервере**. Пользователи не открывают файл базы по сети — они работают через HTTP API.

Для одной кафедры это даёт:

- минимальный состав офлайн-комплекта;
- атомарные транзакции;
- WAL, внешние ключи и проверку целостности;
- FTS5 для полнотекстового поиска;
- простое резервирование и восстановление;
- меньше эксплуатационных отказов, чем у преждевременно введённой распределённой инфраструктуры.

Хранилище изолировано предметными сервисами. Переход на PostgreSQL предусматривается при подтверждённой потребности: несколько подразделений, высокая конкуренция записи, репликация или тяжёлая аналитика. Подробнее: [`docs/adr/0002-sqlite-first.md`](docs/adr/0002-sqlite-first.md).

## Быстрый запуск

Требуется Node.js `24.15+`. Для DOCX/ODT нужен `unzip`, для PDF — `pdftotext` из `poppler-utils`.

```bash
mkdir -p data
npm run migrate
npm start
```

Значения по умолчанию подходят для локального запуска. Для изменения путей и порта передайте переменные окружения явно, например `KAFEDRA_PORT=8090 npm start`. Файл `.env.example` предназначен для systemd `EnvironmentFile` и других менеджеров процессов; приложение не загружает его неявно.

В отдельном терминале:

```bash
npm run worker
```

Откройте:

```text
http://127.0.0.1:8080
```

Для локальной проверки можно использовать Node.js 22.13+, но целевой runtime проекта закреплён на Node.js 24, где `node:sqlite` имеет более высокий статус готовности.

## Структура проекта

```text
apps/
  api/                 HTTP API и статический интерфейс
  worker/              фоновая обработка документов
packages/
  config/              конфигурация
  core/                ошибки, идентификаторы, журналирование
  storage/             SQLite, миграции, очередь, поиск
  document-intake/     форматы, blob-хранилище, извлечение текста
  protocols/           разбор и сохранение протоколов
  calendar/            календарные запросы
public/                 операторский интерфейс
migrations/             последовательные SQL-миграции
deploy/                 systemd, nginx, установка
scripts/offline/        сборка и проверка автономного комплекта
docs/                   архитектура, решения и план развития
```

## API первой версии

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/system/health` | состояние базы и версии схемы |
| `GET` | `/api/overview` | показатели главной страницы |
| `POST` | `/api/documents` | потоковая загрузка файла |
| `GET` | `/api/documents` | список документов |
| `GET` | `/api/documents/:id` | карточка документа |
| `GET` | `/api/calendar` | события за период |
| `POST` | `/api/calendar` | ручное событие |
| `GET` | `/api/review` | очередь проверки |
| `POST` | `/api/review/:id/resolve` | закрытие вопроса |
| `GET` | `/api/search?q=...` | полнотекстовый поиск |

Загрузка выполняется сырым телом запроса. Обязательный заголовок — `X-File-Name`. Необязательный `X-Document-Type: protocol` принудительно включает шаблон протокола. Веб-интерфейс формирует запросы автоматически.

## Данные и пути

По умолчанию:

```text
data/kafedra-planner.sqlite3
data/blobs/ab/cd/<sha256>
data/tmp/
```

Промышленное размещение:

```text
/opt/kafedra-planner/releases/<version>  код
/opt/kafedra-planner/current             активная версия
/var/lib/kafedra-planner                 база и файлы
/etc/kafedra-planner                     конфигурация
/var/log/kafedra-planner                 журналы systemd
```

Код версии никогда не содержит рабочую базу или загруженные документы.

## Автономный комплект

```bash
npm run bundle:offline
npm run bundle:verify -- release/kafedra-planner-0.1.0-alpha.1.tar.gz
```

Сборщик формирует манифест SHA-256. Для целевой Astra Linux в комплект дополнительно помещается официальный Node.js runtime конкретной версии и набор проверенных системных пакетов. Поддержка ОС объявляется только после запуска целевого акта, а не по факту успешной сборки на машине разработчика.

## Принципы, унаследованные из Docomator и Planner Solving

- модульный монолит вместо преждевременных микросервисов;
- явная композиция приложения;
- один источник истины;
- атомарные изменения;
- неизменяемые исходники и ревизии;
- фоновые операции переживают перезагрузку страницы и процесса;
- ошибка одного файла не отменяет пакет;
- замечание всегда содержит безопасное решение и действие оператора;
- ручная коррекция переопределяет автоматику, а не служит обязательным препятствием;
- офлайн-поставка проверяется манифестом и smoke-test;
- все пользовательские тексты короткие и предметные.
