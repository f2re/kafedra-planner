# Кафедра Planner

Автономная рабочая система кафедры: календарь, задачи, документы, решения, сроки, планы работы, научная и педагогическая деятельность.

Система сохраняет исходный документ, извлекает проверяемые сведения, связывает их с календарём и поиском и показывает оператору только те вопросы, которые нельзя решить надёжно автоматически.

> Текущий статус: **release candidate `0.1.0-rc.5`**. Основные рабочие контуры, локальная авторизация, объектные права, персональная доставка уведомлений, проверяемые резервные копии, автоматический откат обновления и единый обучаемый UX во всём операторском интерфейсе реализованы. Перед стабильным релизом остаётся целевая эксплуатационная приёмка на Astra Linux/Debian.

## Что видит оператор

После открытия системы сразу показывается календарь текущего месяца.

```text
Календарь месяца
├─ переключение: месяц / неделя / задачи
├─ события и контрольные сроки
├─ записи на сегодня и ближайшие семь дней
├─ центр уведомлений
├─ создание события или задачи в одном листе
└─ переход к документу, плану, шаблону или вопросу проверки
```

На мобильном экране боковая панель заменяется нижними вкладками. На большом экране её можно скрыть, чтобы календарь занимал всю ширину.

## Что уже работает

### Календарь и задачи

- основной экран — текущий месяц;
- недельное представление;
- список задач с группами `Просрочено`, `Сегодня`, `Предстоящие`, `Выполнено`;
- ручные события и задачи;
- категории: наука, образование, организация, повседневная работа;
- важность и комментарии;
- завершение и возврат задачи;
- напоминания в день события, за час, день, три дня или неделю;
- серверное состояние уведомлений: прочитано и скрыто;
- автоматические задачи из сроков решений протокола и пунктов планов;
- человекочитаемое происхождение автоматической записи и переход к исходному объекту.

### Персональная доставка уведомлений

Внутренний центр уведомлений работает всегда и не зависит от внешних сервисов. При необходимости сотрудник может дополнительно включить персональный внешний канал:

- SMTP через локальный или сетевой почтовый сервер;
- Telegram как необязательный адаптер;
- немедленную доставку только существенных событий;
- ежедневную и еженедельную сводку;
- тихие часы и свой часовой пояс;
- отдельную эскалацию руководителю только для проверки и риска срыва;
- автоматические повторы без создания второго outbox-сообщения;
- административную диагностику и ручной повтор только после исчерпания автоматических попыток.

Outbox использует существующую устойчивую очередь, но имеет меньший приоритет, чем обработка документов. Отключение внешней доставки ставит только такие задания на паузу и не влияет на document intake или внутренние уведомления.

Подробности: [`docs/NOTIFICATION_DELIVERY.md`](docs/NOTIFICATION_DELIVERY.md).

### Документы

- потоковая загрузка одного или нескольких файлов;
- неизменяемое blob-хранилище и дедупликация по SHA-256;
- версии документов;
- фоновая обработка, переживающая закрытие страницы и перезапуск worker;
- TXT, Markdown, CSV, JSON, DOCX, ODT и PDF;
- автоматическое определение протокола заседания;
- номер, дата, председатель, секретарь, присутствующие, повестка и решения;
- ответственные и сроки;
- доказательство происхождения: версия документа и диапазон строк;
- полнотекстовый поиск.

### Заседания кафедры

Раздел `Заседания` ведёт заседание от повестки до готового протокола и выписки, не требуя LLM или внешнего сервиса.

- в настройках кафедры выбираются DOCX-шаблоны протокола и выписки, кворум, председатель и секретарь;
- новое заседание получает дату, номер протокола и снимок этих настроек;
- повестка — плотный нумерованный список вопросов `1…N`;
- вопрос добавляется вручную, из пункта плана или из открытой задачи с сохранением связи с источником;
- для вопроса фиксируются `Слушали`, `Обсудили` и `Решили`;
- полный протокол содержит всю повестку;
- выписка формируется по произвольному набору исходных номеров, например только по вопросам 4 и 8;
- повторное формирование неизменённого документа идемпотентно;
- вопрос и решения индексируются локальным поиском, а пункт плана показывает обратную ссылку `Рассмотрено на заседании кафедры: протокол №… от … · вопрос …`;
- существующий импорт готовых протоколов сохранён и совместим с новым контуром.

Подробности и DOCX-маркеры: [`docs/MEETINGS.md`](docs/MEETINGS.md).

### Обучаемый, но стабильный интерфейс

Preference-layer действует во всём операторском интерфейсе и сокращает повторный ввод, не меняя геометрию экранов. Каждый повторяемый контрол относится к одному из четырёх режимов: `safe-default`, `rank-only`, `domain-derived` или `never-learn`.

- для безопасного нового действия частый **явный** выбор может стать следующим значением по умолчанию;
- в фильтрах и при редактировании существующего объекта статистика только ранжирует рабочие варианты: нейтральный фильтр и сохранённое значение не подменяются;
- предметная автоматика сильнее статистики: конкретный день календаря, дата существующего объекта, найденный по структуре руководитель, вычисленный период плана и специфическая эвристика шаблона имеют приоритет;
- обучаемая дата хранится не как устаревающий `YYYY-MM-DD`, а как ограниченное относительное смещение `d:N` от понятной базовой даты;
- учитываются только реальные действия человека; программные подстановки и синтетические DOM-события частоту не увеличивают;
- один нативный выбор, породивший `input` и `change`, учитывается один раз;
- manager/admin может получать персональный рабочий профиль, а `staff` всегда привязан к сотруднику своего аккаунта;
- кнопки, вкладки, секции и основные поля никогда не переставляются по статистике;
- пароли, токены, логины, поисковые запросы, свободный деловой текст, роли, ACL, подтверждение/возврат/удаление и другие решения с последствиями не обучаются;
- в штатной авторизованной эксплуатации предпочтения хранятся на сервере по аккаунту; `localStorage` используется только как автономный fallback при отключённой авторизации;
- ошибка слоя предпочтений не блокирует сохранение предметного действия.

Например, если пользователь обычно создаёт научную задачу на срок `+7 дней`, форма может предложить такую категорию и относительный срок. Но клик по конкретному дню календаря или открытие уже сохранённой задачи всегда оставляет фактическую дату этого контекста.

Подробный контракт и разрешённые контексты: [`docs/ADAPTIVE_UX.md`](docs/ADAPTIVE_UX.md).

### Планы работы

Раздел `Планы` предназначен для планов кафедры, факультета, подразделения, организации и личных планов сотрудников.

- загрузка готового DOCX/ODT/XLSX/ODS/PDF/TXT через обычный документный контур;
- календарные и учебные периоды с корректным наследованием года для неполных дат;
- пункты, ответственные, направления, ожидаемые результаты и доказательства по строкам/ячейкам;
- фасетные фильтры по виду, году, направлению и ответственному;
- неоднозначная строка сохраняется без выдуманного срока и не блокирует остальной план;
- исправление пункта выполняется на месте, исходное `evidence_json` не изменяется;
- исправление и отмена синхронно обновляют календарь, поиск, фасеты и очередь проверки;
- существующая календарная запись при коррекции обновляется с сохранением ID и истории ревизий;
- DOCX существующего плана можно сохранить как неизменяемый образец;
- следующий календарный/учебный год подставляется только в подтверждённые OOXML-якоря;
- строки Word клонируются вместе со стилями;
- сформированный DOCX снова проходит штатный document intake и автоматически создаёт новый план и календарные сроки;
- генерация идемпотентна и не создаёт второй документ при повторе того же запроса.

Подробный операторский сценарий: [`docs/PLANS_OPERATIONS.md`](docs/PLANS_OPERATIONS.md).  
Архитектура импорта и формирования: [`docs/PLANS.md`](docs/PLANS.md).

### Шаблоны извлечения

Оператор может один раз настроить новый вид документа:

```text
обработанный документ
→ щелчок по строке
→ название и тип поля
→ правило извлечения
→ проверка результата
→ сохранение шаблона
→ автоматическая обработка следующих документов
```

Поддерживаются правила:

- значение после подписи в той же строке;
- следующая непустая строка;
- вся строка;
- текст между двумя подписями.

Типы значений:

- короткий и длинный текст;
- дата;
- число;
- да / нет.

Шаблон хранит источник, поля, обязательность, правила сопоставления и доказательства. Если обязательное поле не найдено, уже извлечённые данные не теряются: система создаёт один понятный вопрос оператору.

## Основные пользовательские сценарии

Полный UX-контракт и критерии приёмки находятся в [`docs/UX_FLOWS.md`](docs/UX_FLOWS.md).

Ключевые правила:

- система сразу открывает основную работу, а не сводную панель;
- переключение представления не меняет раздел;
- повторяющийся явный выбор может стать следующим безопасным значением по умолчанию, но не переставляет элементы интерфейса;
- обычный структурированный фильтр остаётся нейтральным: статистика меняет только порядок вариантов;
- даты безопасных новых действий обучаются только как относительное смещение; конкретно выбранная или уже сохранённая дата выше статистики;
- надёжная предметная автоматика выше learned default;
- сохранённое значение существующего объекта выше обученной подсказки;
- обратимые действия не требуют лишних подтверждений;
- ошибки и статус показываются рядом с объектом;
- модальные предупреждения используются только для действительно критических ситуаций;
- фоновая обработка не блокирует календарь;
- каждый новый сценарий получает автоматический тест потока.

## Инспектор и обратимые изменения

Календарная запись и документ открываются в правой инспекторной панели без ухода с текущего экрана. На мобильном устройстве та же панель становится нижним листом.

- событие можно просмотреть, изменить и завершить из одного места;
- автоматическая запись показывает исходный документ или план;
- документ показывает извлечённые поля, доказательства по строкам, протоколы и вопросы проверки;
- событие можно перенести на другой день перетаскиванием;
- перенос записывается в журнал и восстанавливается кнопкой `Отменить`;
- корректировка пункта плана не уничтожает исходное машинное значение и доказательство;
- фильтры категорий и типа записи сохраняются между сеансами;
- черновик мастера шаблона сохраняется на сервере и восстанавливается после закрытия браузера.

## Почему Node.js

Для платформенного ядра используется **Node.js 24 LTS** и стандартные модули Node.js без обязательных runtime-зависимостей npm.

Это даёт:

- один runtime для API, worker, OOXML и интерфейса;
- простую автономную поставку под Astra Linux;
- потоковую работу с файлами;
- встроенные SQLite и тестовый runner;
- возможность подключать Python только как специализированный адаптер для OCR, ML или научных расчётов.

DOCX и ODT читаются из OOXML/XML через системный `unzip`. PDF преобразуется `pdftotext`. LibreOffice и OCR подключаются отдельными адаптерами. Генеративная модель не является обязательной частью конвейера.

## Почему SQLite на первом этапе

SQLite находится только на сервере. Пользователи работают через HTTP API и не открывают файл базы по сети.

Для одной кафедры это обеспечивает:

- минимальный автономный комплект;
- транзакции, WAL и внешние ключи;
- FTS5;
- простое резервирование;
- меньше эксплуатационных отказов.

Слой хранения изолирован предметными сервисами. Переход на PostgreSQL предусматривается при появлении нескольких подразделений, высокой конкуренции записи, репликации или тяжёлой аналитики.

## Быстрый запуск

Требуется Node.js `24.15+`. Для DOCX/ODT нужен `unzip`, для PDF — `pdftotext` из `poppler-utils`.

```bash
mkdir -p data
npm run migrate
npm start
```

В отдельном терминале:

```bash
npm run worker
```

Откройте:

```text
http://127.0.0.1:8080
```

Для другого порта:

```bash
KAFEDRA_PORT=8090 npm start
```

## Автономный комплект

Полный bundle собирается на эталонной Debian/Astra той же версии и архитектуры, что целевой сервер:

```bash
npm run bundle:offline
```

В `release/` появляются архив, SHA-256, `install-kafedra-planner.sh` и краткая инструкция. На целевой машине обычная установка/обновление — одна команда:

```bash
sudo ./install-kafedra-planner.sh
```

В full bundle входят Node.js 24 LTS, managed CPython для распознавания и полное `.deb`-замыкание Tesseract `rus+eng`, Poppler, LibreOffice и системных CLI. `npm`, `pip`, system Python и Интернет на target не требуются. Инженерный runtime-only архив сохранён как `npm run bundle:offline:runtime`. Подробности: [`docs/OFFLINE_INSTALL.md`](docs/OFFLINE_INSTALL.md).

## Структурный источник документа

Версия `0.1.0-alpha.4` сохраняет адресуемые фрагменты исходника:

- абзацы и ячейки DOCX;
- абзацы и ячейки ODT/ODS;
- листы и ячейки XLSX;
- страницы и координаты текстового слоя PDF;
- строки текстовых файлов.

В инспекторе оператор может показать доказательство конкретного поля, выбрать другой фрагмент и сохранить ручное исправление. Машинный результат при этом не стирается: исправление хранится отдельной ревизией с причиной и выбранным источником.

Подробности: [`docs/STRUCTURED_DOCUMENTS.md`](docs/STRUCTURED_DOCUMENTS.md).

## Авторизация и роли

Авторизация включена по умолчанию. Локальные аккаунты связаны со справочником сотрудников; поддержаны роли сотрудника, руководителя и администратора. При первой полной offline-установке администратор создаётся автоматически; временный пароль сохраняется только в `/root/kafedra-planner-first-login.txt`.
